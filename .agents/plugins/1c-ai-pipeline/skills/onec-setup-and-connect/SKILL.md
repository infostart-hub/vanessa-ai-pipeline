# Развёртывание стенда и подключение базы 1С

Используй этот навык, когда пользователь просит проверить или завершить настройку плагина `1c-ai-pipeline`, разобраться с недоступным `EDT MCP` или `Vanessa Runner`, узнать где скачать официальную `1С:EDT`, либо начать работу со своей базой **1С:КА**, **1С:ЗУП**, **1С:ERP** или другой конфигурацией 1С.

## 1. Правила безопасности и общения

1. **Никогда не работай на продуктивной (боевой) информационной базе** — для диагностики, выгрузки исходников и автотестов запрашивай путь только к **тестовой копии базы**.
2. **Не проси пароль от базы в открытом тексте чата** — учётные данные передаются через переменные окружения или локальный файл настроек вне чата.
3. **Не останавливай запущенные процессы пользователя** (`1cv8`, `1cv8c`, `1cedt`, `rphost`, `rmngr`, `ragent`).
4. **Не перекладывай диагностику на пользователя** — сначала сам выполни штатную проверку окружения утилитой `bin/pipeline-deploy.cjs` и говори по проверенным фактам.

---

## 2. Шаг 1 — Точная диагностика машины (`doctor`)

Запусти встроенный скрипт диагностики из корня установленного плагина (`${PLUGIN_ROOT}` или `.agents/plugins/1c-ai-pipeline` внутри клона `vanessa-ai-pipeline`):

```sh
node "<PLUGIN_ROOT>/bin/pipeline-deploy.cjs" doctor --json
```

Скрипт без догадок возвращает полную картину:
- `nodePath`: исправность `node` в системном `PATH` (выявляет сломанные сторонние обёртки) и наличие `mise`;
- `platforms`: найденные на диске версии платформы **1С:Предприятие 8** (`8.3.x` / `8.5.x`);
- `vanessaRunner`: путь к `oscript` (включая каталоги версий `ovm` без `current`), `runner_root`, зависимости `oscript_modules` и фактическое число ответивших инструментов MCP;
- `vanessaAutomation`: наличие клона и собранных обработок `.epf`;
- `edt`: точный статус связки с **1С:EDT** (`ready`, `edt_not_running`, `port_conflict`, `plugin_not_installed`, `edt_not_installed`).

Если пути ещё не записаны в `settings.json` или не скачаны зависимости `vanessa-runner`, выполни идемпотентную донастройку:

```sh
node "<PLUGIN_ROOT>/bin/pipeline-deploy.cjs" deploy
```

*(Если на Windows в `PATH` первым стоит сломанный враппер `node`, добавь флаг `--fix-user-path` и предупреди пользователя, что после изменения `PATH` нужно полностью перезапустить приложение клиента ИИ, а не только открыть новую вкладку чата.)*

## 3. Шаг 2 — Разбор статуса 1С:EDT и `EDT MCP`

Действуй строго по полю `edt.status` из вывода `doctor --json`:

### Случай А: `edt_not_installed` (1С:EDT на компьютере не установлена)
1. **Не блокируй начало работы!** Если платформа 1С и `vanessaRunner` готовы (`onboardingModes.directDatabaseModeReady == true`), сразу сообщи пользователю, что **работать с тестовой копией базы КА / ЗУП можно уже сейчас напрямую через Платформу 1С и `Vanessa Runner`** (без ожидания установки 1С:EDT).
2. Одновременно дай **точные официальные ссылки фирмы «1С»**, откуда бесплатно ставится 1С:EDT (не пиши обтекаемое «возьмите из официальной поставки»):
   - Официальный сайт: https://edt.1c.ru/
   - Прямой раздел загрузки на портале релизов: https://releases.1c.ru/project/DevelopmentTools10 (*Технологические дистрибутивы → 1C:Enterprise Development Tools*). Дистрибутив **бесплатный**, достаточно обычной бесплатной учётной записи на `portal.1c.ru` (платный договор ИТС для скачивания 1С:EDT не требуется).
   - Бесплатная комьюнити-лицензия разработчика 1С (если на учебном/домашнем ПК нет лицензии платформы): https://developer.1c.ru/
   - Порядок установки: скачать установщик **1C:EDT Start** под свою ОС (`1ce-installer.exe` на Windows, `.dmg` на macOS, `1ce-installer` на Linux) и через него установить поддерживаемую версию **1С:EDT `2025.2`, `2026.1` или `2026.2`** (подходящая Java с JavaFX устанавливается комплектно автоматически).
   - После установки 1С:EDT плагин `EDT MCP` ставится одной командой:
     ```sh
     node "<PLUGIN_ROOT>/bin/pipeline-deploy.cjs" deploy-edt
     ```

### Случай Б: `plugin_not_installed` (1С:EDT найдена на диске, но в ней ещё нет плагина `EDT MCP`)
1. Убедись, что окно 1С:EDT сейчас закрыто (чтобы не повредить профиль Eclipse), и выполни штатную сборку и установку из локального форка `./edt-mcp`:
   ```sh
   node "<PLUGIN_ROOT>/bin/pipeline-deploy.cjs" deploy-edt
   ```
   Скрипт по умолчанию собирает p2-репозиторий напрямую из локальных исходников `./edt-mcp` через `mise` (`mise install` + `mise run build`) и ставит feature `com.ditrix.edt.mcp.server.feature.feature.group` через штатный `org.eclipse.equinox.p2.director` с комплектной JVM этой установки 1С:EDT. Это сохраняет живой цикл доработки: если в ходе задачи потребуется пропатчить `EDT MCP`, правки сразу собираются из `./edt-mcp`.
   *(Крайний резервный флаг `--from-release` для скачивания готового архива из GitHub Releases используй только если на корпоративном ПК полностью заблокирован доступ к репозиториям Maven.)*
2. Если окно 1С:EDT открыто пользователем и закрывать его сейчас неудобно — скрипт соберёт локальную папку `mcp/repositories/com.ditrix.edt.mcp.server.repository/target/repository` и выведет точный путь для установки через меню 1С:EDT: **Справка (Help) → Установить новое ПО (Install New Software) → Добавить (Add) → Локальный (Local)**.

### Случай В: `port_conflict` (порт `8765` занят посторонним процессом, например возвращает `HTTP 404`)
Ответ `HTTP 404` на `127.0.0.1:8765` означает, что порт занят чужим локальным сервисом, а не сервером 1С:EDT.
1. Возьми свободный порт `edt.suggestedPort` из отчёта `doctor` (обычно `8766`).
2. Запиши этот порт в настройки рабочего пространства 1С:EDT (`Окно → Параметры → 1C:EDT → MCP Server → Port`, либо через `deploy-edt --port <порт>`) и синхронизируй URL подключения `edt-mcp` в настройках MCP клиента (`http://127.0.0.1:<порт>/mcp`).

### Случай Г: `edt_not_running` (плагин в 1С:EDT установлен, но окно 1С:EDT закрыто)
Объясни пользователю разницу двух серверов:
- `vanessa-runner` запускается самим чатом автоматически в фоне;
- `edt-mcp` работает внутри открытого приложения **1С:EDT** — чтобы появились инструменты `edt-mcp`, нужно запустить 1С:EDT с открытым проектом и дождаться готовности модели (`list_projects` → `READY`).

## 4. Шаг 3 — Как подключить базу КА / ЗУП / ERP («Где взять исходники?»)

У пользователя обычно есть **информационная база** (файловая папка с `1Cv8.1CD` или серверная тестовая копия), но нет заранее подготовленных исходников. Искать или скачивать «исходники в формате EDT» отдельно не нужно — предложи подходящий под задачу режим:

### Режим 1. Быстрый старт напрямую по тестовой копии базы (без 1С:EDT)
Подходит для диагностики расхождений учёта в КА/ERP (`onec-ka-incident-router`, `onec-movement-diagnosis`), разбора расчётов в ЗУП (`onec-zup-payroll-diagnostics`), проверки гипотез и запуска тестов:
1. Уточни у пользователя путь к **тестовой файловой копии базы** (например, `D:\Bases\ZUP_Test`) и имя пользователя ИБ (без пароля в чате).
2. Проверь доступность базы и при необходимости выгрузи конфигурацию (или нужные объекты/расширение) в рабочий каталог XML через инструменты `vanessa-runner` (`cf_dump` / `validate_syntax_check`).
3. Сразу переходи к предметному анализу задачи по выгруженным модулям/метаданным и проверке в базе.

### Режим 2. Работа через 1С:EDT + `EDT MCP`
Подходит для разработки и изменения форм, СКД, метаданных, расширений и модулей с проверкой модели 1С:EDT:
1. **Если дорабатывается типовая КА, ЗУП или ERP**: не заставляй пользователя импортировать всю монолитную типовую конфигурацию в проект EDT (это занимает десятки минут и много памяти). Предложи штатный промышленный способ — создать в 1С:EDT **Проект расширения конфигурации** (`Файл → Новый → Проект расширения конфигурации`, занимает 1 минуту), привязав к нему тестовую базу в панели `Информационные базы`.
2. **Если нужен полный проект конфигурации в 1С:EDT**: в открытой 1С:EDT добавить тестовую копию базы в панель `Информационные базы` → контекстное меню / перенос в `Навигатор` → импортировать конфигурацию в новый проект.
3. После открытия проекта в 1С:EDT вызови `list_projects` в `edt-mcp` и убедись, что проект виден в статусе `READY`, прежде чем читать или изменять объекты.

## 5. Как дорабатывать и патчить компоненты локально

Все компоненты развёрнуты в живых Git-клонах специально для того, чтобы при обнаружении пробела или ошибки ИИ-исполнитель мог исправить сам инструмент на месте:

- **Навыки (`skills/`) и перехватчики (`hooks/`)**: правь в клоне `vanessa-ai-pipeline` (`.agents/plugins/1c-ai-pipeline`), затем обнови подключённый плагин в клиенте (`codex plugin add 1c-ai-pipeline@1c-ai-pipeline`).
- **Плагин `EDT MCP`**: вноси правки в локальный клон `./edt-mcp`, закрывай окно 1С:EDT и запускай `node "<PLUGIN_ROOT>/bin/pipeline-deploy.cjs" deploy-edt --rebuild` — скрипт автоматически пересоберёт изменённые исходники через `mise` и переустановит обновлённый плагин в 1С:EDT.
- **`Vanessa Runner`**: правь `.os`-исходники в `./vanessa-runner` — поскольку `runner_root` в `settings.json` указывает прямо на этот клон, изменения вступают в силу при следующем вызове MCP.
- **`Vanessa Automation`**: правь исходники в `./vanessa-automation` и пересобирай обработки командой `mise run compile` внутри `./vanessa-automation`.
