# Текущий проект EDT

Исполнитель использует уже подключённый Agent Plugin edt-mcp.
Пакет onec не создаёт второе подключение, MCP-сервер или парсер .mdo.
Endpoint и выбранный workspace задаёт хост. Проверить initialize/tools/list.

1. `list_projects` определяет точное имя, путь, вид и состояние проекта.
   При неоднозначности запросить уточнение у пользователя. Не брать первый проект.
2. Прочитать `get_tool_guide` для нужных инструментов и их текущие схемы.
3. `get_configuration_properties` с явным `projectName` возвращает имя
   конфигурации, совместимость, языки и свойства. Инструмент допускает отсутствие
   projectName и тогда выбирает первый проект; для этого навыка так нельзя.
4. `get_metadata_objects` с тем же projectName возвращает состав и Total.
   Лимит задаётся явно по текущему guide. Сохранить факт усечения.
   Не выдавать счётчики показанных строк за полный состав.
   Для больших проектов сузить чтение по metadataType в рамках исследования,
   сверяя полноту; не придумывать offset, которого нет в текущей схеме.
5. Для отдельных объектов использовать `get_metadata_details`: objectFqns
   строить по Type и программному Name из ответа, не по синониму.
   Его секция Errors может содержать отказ отдельного объекта даже при
   isError=false. Такой объект не считать успешно прочитанным.

Результат: проект и путь EDT, свойства, наблюдаемый состав и ограничения.
Исходные ответы остаются материалами операции в хосте. Subsystem в
get_metadata_objects — только верхний уровень; для полного дерева требуется
штатный list_subsystems по его актуальному guide.
Базу и расширение исследовать как разные проекты. Проект внешних обработок
не считать конфигурацией. Ответы нескольких вызовов не атомарны и не дают
SHA-256 снимка проекта; не приписывать им общий хеш версии.

Недоступный EDT означает отсутствие наблюдения EDT. Экспорт, XML-скрипт,
редактирование .mdo, сборка и запуск базы не являются продолжением этого чтения.
