# Совместимость `FormatVersion`, ловушки разборки `EPF`/`ERF` и заимствования `CFE`

Практическая памятка по файловым выгрузкам Конфигуратора 1С (`DumpConfigToFiles` / `LoadConfigFromFiles`, `DumpExternalDataProcessorOrReportToFiles` / `BuildExternalDataProcessorOrReportFromFiles`) и пакетам расширений.

## 1. Соответствие версии платформы и `FormatVersion` XML-выгрузки

При переносе исходников между стендами разработчиков и сборочным контуром версия формата иерархической XML-выгрузки не должна превышать версию платформы на целевом сборочном сервере:

| Платформа 1С:Предприятие | Корневой `FormatVersion` XML-выгрузки |
|---|---|
| `8.3.24` | `2.17` |
| `8.3.25` | `2.18` |
| `8.3.26` | `2.19` |
| `8.3.27` | `2.20` |
| `8.5.x` | `2.21` |

- Попытка загрузить выгрузку со старшим `FormatVersion` в младшую платформу завершается отказом чтения формата XML (при этом не путай `FormatVersion` файлов выгрузки со свойством `РежимСовместимости` самой конфигурации!).
- Ручное понижение числа `version="2.xx"` в заголовках XML без перевыгрузки штатным инструментарием запрещено: между версиями меняются схемы дочерних элементов форм и прав.

## 2. Критические ловушки разборки и сборки внешних обработок / отчётов (`EPF` / `ERF`)

1. **Разборка `EPF`/`ERF` на пустой информационной базе уничтожает ссылочные типы**:
   - Если выполнить `/DumpExternalDataProcessorOrReportToFiles` в пустой базе, где нет метаданных целевой конфигурации (`Справочник.Номенклатура`, `Документ.РеализацияТоваровУслуг`, регистры), платформа **завершит команду с кодом `0`**, но в `Form.xml` и описании реквизитов заменит все прикладные ссылочные типы на примитивный `xs:string` или неразрешимые идентификаторы типов, а у таблиц формы очистит связанные колонки!
   - Последующая сборка из таких исходников даст внешнюю обработку со сломанными полями ввода. Всегда разбирай и собирай `EPF`/`ERF` только на информационной базе с загруженной целевой конфигурацией (или через проект внешних объектов в 1С:EDT с привязанным базовым проектом конфигурации).
2. **Кодировка модулей в выгрузке Конфигуратора (`UTF-8 с BOM`)**:
   - Файлы `Ext/*.bsl` в классической XML-выгрузке Конфигуратора должны сохранять маркер `UTF-8 BOM` (`EF BB BF`). Перезапись файла в `UTF-8 без BOM` сторонним скриптом при загрузке на части окружений Windows приводит к искажению кириллических литералов и комментариев.

## 3. Ловушки файловых выгрузок основной конфигурации и расширений (`CFE`)

1. **Служебные файлы `ConfigDumpInfo.xml` и `ParentConfigurations.bin`**:
   - `ConfigDumpInfo.xml` хранит контрольные версии объектов для инкрементальной выгрузки/загрузки; ручное редактирование этого файла ломает частичную синхронизацию ИБ.
   - `Ext/ParentConfigurations.bin` хранит бинарные правила поддержки поставщика («замок»). Удаление или подмена этого файла снимает конфигурацию с поддержки без штатной процедуры Конфигуратора и блокирует последующую установку обновлений `.cfu`.
2. **Повторное заимствование формы в расширение поверх уже сделанных доработок**:
   - Повторный запуск генератора заимствования объекта/формы в `CFE` поверх уже доработанной заимствованной управляемой формы перезаписывает `Form.xml` базовым состоянием, оставляя в модуле формы расширения висячие обработчики несуществующих элементов и команд. Дорабатывай уже заимствованную форму точечно через `edt-mcp-project-forms`, предварительно сверив `BaseForm` при обновлении релиза поставщика.
3. **Идентификаторы элементов управляемой формы (`id`) и парные узлы (`ContextMenu`, `ExtendedTooltip`)**:
   - В `Form.xml` каждый визуальный элемент обязан иметь уникальный целочисленный `id` в пределах всей формы и обязательные дочерние узлы сопровождения (`ContextMenu`, `ExtendedTooltip`, а у полей ввода/таблиц — свои служебные подэлементы). Дубликат `id` или пропуск обязательного дочернего узла делает форму нечитаемой при загрузке в ИБ — поэтому при наличии 1С:EDT всегда предпочитай `edt-mcp-project-forms` прямой правке сырого XML.
