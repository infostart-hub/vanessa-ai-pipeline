# Доработка через расширение конфигурации

Используй навык, когда задача меняет поведение, форму или состав объекта конфигурации, которую проект получает от поставщика или из типового решения: модуль объекта или менеджера, общий модуль, форму, реквизит, табличную часть.

Навык задаёт предметное решение. Заимствование, чтение и запись метаданных и модулей выполняет EDT MCP: навык `edt-mcp-project-metadata` для заимствования и состава, `edt-mcp-project-forms` для форм, `edt-mcp-project-local-fix` для текста метода.

## Сначала установи, чей объект

Не предполагай путь по названию конфигурации или по наличию расширений в проекте. Установи через EDT:

- точный проект базовой конфигурации и проекты расширений, связанные с ней;
- стоит ли конфигурация или объект на поддержке поставщика и разрешено ли его изменение;
- есть ли у объекта собственный префикс проекта или он типовой;
- какое расширение уже служит этой задаче или этому функциональному блоку, его префикс имён и назначение.

Если факты недоступны, назови их неизвестными в исследовании и не выбирай путь за пользователя.

## Выбери путь

| Ситуация | Путь |
|---|---|
| Объект типовой, конфигурация на поддержке, изменение выражается расширением | Расширение. Типовой код и метаданные не правь |
| Объект собственный (префикс проекта, снят с поддержки, создан проектом) | Прямая правка в базовой конфигурации |
| Нужное свойство нельзя изменить расширением на этой платформе и в этом режиме совместимости | Не обходи ограничение. Опиши ограничение и варианты владельцу; снятие с поддержки — решение владельца, не исполнителя |

Выбор пути и его основания запиши в спецификации: проект, расширение, заимствуемые объекты, перехватываемые методы.

## Заимствуй только нужное

- Заимствуй объект, форму или общий модуль через `adopt_metadata_object`: базовая конфигурация — `projectName`, расширение — явный `extensionProjectName`, если расширений больше одного.
- Заимствуй минимальный состав. Заимствованная форма без реквизитов объекта показывает только свои элементы; чтобы вывести на неё данные объекта, заимствуй используемые реквизиты.
- Реквизиты заимствуются у объекта из типа основного реквизита формы. Обычно это владелец формы; у формы обработки с основным реквизитом другого объекта — этот объект.
- Отдельный реквизит, табличную часть, реквизит табличной части, измерение или ресурс заимствуй без формы: `adopt_metadata_object` с FQN элемента, например `Catalog.Товары.Attribute.Вес` или `Document.Заказ.TabularSection.Товары.Attribute.Цена`. Родитель заимствуется вместе с ним.
- Код модулей расширения читает реквизиты базового объекта без заимствования. Заимствуй реквизит, только когда его выводит собственная форма расширения или табличной части нужны собственные реквизиты.
- Собственная форма расширения видит только заимствованные реквизиты объекта; путь к незаимствованному — ошибка «Неверный путь к данным».
- Собственный реквизит в заимствованной табличной части не принимается при обновлении базы у плана видов характеристик, плана счетов и плана видов расчёта; у бизнес-процесса и задачи — только начиная с платформы 8.3.25. До такого решения сверь вид объекта и версию платформы проекта; если ограничение действует, иди по третьей строке таблицы путей.
- Новый реквизит, табличную часть, команду или форму добавляй в объект расширения, а не в базовый объект. Имена новых объектов и реквизитов следуют правилам проекта; имена новых методов расширения — префиксу этого расширения, чтобы не столкнуться с другими расширениями.
- Новый элемент формы связывай с реквизитом формы или объекта. Связь и видимость проверяй по модели EDT, а не по совпадению имён.

## Выбери перехватчик метода

Перехватчик связывается с методом базового модуля по имени и списку параметров. Сигнатуру, директиву компиляции модуля формы и условие препроцессора бери из актуального базового метода через EDT, а не из памяти или примера.

| Аннотация | Когда | Ограничения |
|---|---|---|
| `&Перед` | Добавить действия до неизменного базового метода | Только для процедуры |
| `&После` | Добавить действия после неизменного базового метода | Только для процедуры |
| `&Вместо` | Заменить поведение или выполнить базовый метод по условию | `ПродолжитьВызов()` вызывает базовый метод и для функции возвращает его значение. Без этого вызова базовое поведение не выполняется: это полная замена, её нужно обосновать |
| `&ИзменениеИКонтроль` | Точечно изменить тело базового метода | Тело — контролируемая копия базового метода. Добавленные строки обрамляются `#Вставка` и `#КонецВставки`, исключённые — `#Удаление` и `#КонецУдаления`. `ПродолжитьВызов()` здесь не используется |

Порядок выбора: сначала `&Перед` или `&После`, затем `&Вместо` с `ПродолжитьВызов()`, затем `&ИзменениеИКонтроль`, и только затем `&Вместо` без базового вызова. Более сильный вид выбирай, когда слабый не выражает требование, и называй причину.

`&ИзменениеИКонтроль` связывает расширение с текстом базового метода. После обновления поставщика расширение может не примениться, пока копия не сверена с новой редакцией. Сверку с базовым методом, сохранение правок и проверку применимости расширения проводи явно перед завершением задачи.

Не правь текст заимствованного модуля вне перехватчиков: заимствованный модуль содержит только методы расширения.

## Чем доказывается результат

Разделяй три факта: диагностика EDT проекта расширения без ошибок, применимость расширения к базе на платформе и в режимах совместимости проекта, поведение пользователя в сценарии. Успешная запись файла или заимствования не доказывает ни применимость, ни поведение. В плане проверки укажи, какой из фактов подтверждает каждый критерий.
