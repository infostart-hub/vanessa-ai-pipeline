# От хозяйственного вопроса к запросу

Начни с результата для роли: какую строку человек должен увидеть и какое действие выполнить. Для обеспечения производства это материал в задании, его потребность, свободное количество и заявка на недостающее. Не заканчивай текстом SQL, если человеку нужен рабочий список.

## Установи смысл данных

Через существующий EDT MCP прочитай реальные имена объектов, реквизитов, табличных частей, измерений, ресурсов, единиц и связей. Прочитай код заполнения источников. Не подставляй знакомые имена из другой конфигурации. Установи:

- что представляет одна строка каждого источника;
- по каким ссылкам источники связаны, где связь один-ко-многим;
- на какой момент, по какой организации, складу и заданию нужен результат;
- что означает количество: норма на изделие, потребность на выпуск, физический остаток, резерв или свободный остаток;
- какие данные и права доступны роли. Недоступные строки не равны нулевому остатку.

Для упрощённого снимка остатков явно назови его снимком, не выдавай его за регистр движений полноценного складского учёта. Не читай уже рассчитанную потребность как независимый источник факта.

## Собери расчёт без размножения строк

Перед соединением приведи независимые источники к нужной детализации. Например, суммируй строки состава по материалу и единице, умножь норму на количество выпуска. Остатки и резервы агрегируй отдельно по тем же ключам. Соединение сырых табличных частей может умножить количество строк и суммы.

Соединяй ссылки совместимых типов, а не представления. Сравнение ссылки реквизита со ссылкой справочника в условии ПО допустимо. Одинаковые наименования не доказывают тождество объектов. РАЗЛИЧНЫЕ не исправляет неверную связь.

ЛЕВОЕ СОЕДИНЕНИЕ сохраняет потребность, для которой нет строки остатка. ЕСТЬNULL заменяет отсутствующий ресурс нулём только после установления его хозяйственного смысла. Отбор правой таблицы в ГДЕ способен убрать такую строку; условия склада ставь при подготовке источника или в ПО.

Свободное количество = физический остаток минус резервы по согласованной модели. Не вычитай резерв повторно из уже свободного остатка. Потребность и остатки должны иметь совместимые единицы; коэффициент пересчёта нельзя придумывать. Дефицит неотрицателен, но отрицательный остаток не прячь без объяснения. В заявку включай только положительный дефицит.

## Язык и исполнение

Пиши многострочный запрос с понятными псевдонимами. Внешние значения передавай параметрами, включая ссылки и перечисления; не склеивай текст пользовательского ввода. СГРУППИРОВАТЬ ПО задаёт детализацию, ИМЕЮЩИЕ отбирает группы, ИТОГИ добавляет итоги. Для промежуточных наборов используй пакет и временные таблицы там, где это упрощает модель.

Сигнатуру виртуальной таблицы уточняй для её вида и версии платформы. Запятые разделяют позиционные параметры; несколько условий одного параметра соединяются И. Отбор до СрезПоследних и после среза имеет разный смысл. Не переносить условия механически ради скорости.

Не заменяй ИЛИ на ОБЪЕДИНИТЬ ВСЕ без анализа пересечения ветвей. Индексирование временных таблиц обосновывай объёмом и использованием. Не объявляй синтаксически допустимые вложенные соединения запрещёнными. Оптимизацию подтверждай замером на целевой базе, а не универсальным порогом строк.

РАЗРЕШЕННЫЕ может скрыть часть результата. Не повышай привилегии ради быстрого запроса и не объявляй скрытые данные отсутствующими. Согласуй полноту результата с правами роли.

Узнай доступные инструменты через каталог MCP. Для статической проверки используй validate_query, если он реально доступен, передав проект и queryText либо modulePath. Не выдумывай execute_query: выполнение в базе обеспечивается доступным штатным Runner или прикладным кодом. Проверка синтаксиса не доказывает правильность результата.

## Доведи до рабочего действия

Добавь в форму понятные колонки с единицами, основание расчёта и главное действие. Сохрани заявку как документ, связанный с заданием; повторное нажатие не должно незаметно создавать вторую заявку. Перед записью пересчитай данные, не доверяй редактируемой таблице клиента. Расчёт потребности не резервирует товар сам по себе.

На контрольных данных проверь материал без остатка, несколько строк одного материала, достаточный остаток, резерв и чужой склад. Проверь созданную заявку и повтор действия. Сохрани фактический результат штатного теста; изображение с надписью «пройдено» не является отчётом прогона. Отдельно сообщи, что проверено в исходниках, а что выполнено в 1С.
