# Развитие поведения прикладного объекта

Сначала установи хозяйственное событие и результат для роли. План и факт — разные данные. Частичное выполнение должно оставлять исходное задание и отдельные документы факта, чтобы мастер видел историю и остаток. Не заменяй новые операции исправлением старого документа задним числом.

## Исследование модели

Через существующий EDT MCP прочитай документ, его модуль объекта, регистры и регистраторы, формы, подписки и расширения. Уточни разрешение проведения, автоматическое удаление движений, режим блокировок и права роли. Название события само по себе не описывает существующую учётную модель.

Выбери место поведения по ответственности:
- ОбработкаЗаполнения переносит данные основания; произвольное СоздатьДокумент не гарантирует её вызов.
- ОбработкаПроверкиЗаполнения помогает человеку заполнить форму; программная запись не гарантирует эту проверку. Обязательные правила любой записи обеспечиваются серверным объектом.
- ПередЗаписью выполняет дозаполнение и проверки до сохранения самого объекта. Сравнивать прежние значения нужно до их замены.
- ПриЗаписи обрабатывает зависимые данные после записи объекта. Изменение собственных реквизитов здесь не является их сохранением.
- ОбработкаПроведения формирует движения факта. ПриЗаписи документа вызывается раньше неё.
- ОбработкаУдаленияПроведения обслуживает отмену. Не считать её зеркальной последовательностью проведения.

Для набора записей обработчики относятся к набору целиком, включая пустой набор. Не выводи количество бизнес-событий из количества вызовов обработчика. Поведение менеджера записи и режима замещения уточняй для версии платформы и конкретного регистра.

## План, факт и повтор

Выбери устойчивое основание факта: задание, заказ или этап. Определи единицу измерения и период. Остаток задания вычисляй по проведённым фактам, а не через прибавление счётчика при каждом сохранении формы.

Движения формируй по сохранённым данным документа. Для обычного проведения достаточно заполнить коллекцию Движения и пометить нужный набор Записывать. Явная запись может требоваться алгоритму контроля остатков — обоснуй её, порядок блокировки и проверки; не переносить запрет или образец механически.

Повторное проведение должно заменять движения данного регистратора. Отмена должна удалять его вклад согласно настройке удаления движений, сохраняя чужой выпуск. Не присваивай Проведен вручную вместо штатного режима записи.

Если запрещён перевыпуск, блокируй область задания перед чтением доступного остатка и учитывай прежний вклад перепроводимого документа. Простое чтение остатка без блокировки не обеспечивает параллельную сдачу двумя мастерами. Внешние вызовы и ожидание человека вынеси из транзакции.

ОбменДанными.Загрузка рассматривай по контракту обмена: пропуск действий допустим, когда нужные движения и инварианты обеспечивает обмен. Безусловный Возврат способен оставить факт без учётного отражения.

## Форма и проверка результата

Рабочее место показывает задание, план, сдано, осталось и список документов факта. Главное действие — оформить очередную сдачу. Документ из списка открывается; подписи и единицы понятны мастеру. Форму собирай средствами EDT MCP, не отдельным макетом, изображающим 1С.

Проверь на локальной тестовой базе два отдельных факта одного задания, повторное проведение первого и отмену второго. Сравни движения по регистратору и итог задания; проверь сохранность соседнего задания. Пользователь должен получить рабочую сдачу и остаток, а не только текст «тест зелёный».

Проверка исходников не доказывает выполнение. Не запускать новые клиенты для каждого чтения: используй установленный Runner и один принадлежащий задаче сеанс. При свежем исключении прочитай модуль и строку, исправь причину и только затем повтори операцию.
