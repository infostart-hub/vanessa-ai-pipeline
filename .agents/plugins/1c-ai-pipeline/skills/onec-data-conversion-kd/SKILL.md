# Конвертация данных 1С: КД 2 и КД 3 (`EnterpriseData`)

Используй этот навык, когда обмен строится на **правилах конвертации данных КД 2 (XML-правила `ПВД` / `ПКО` / `ПКС`)** или на **универсальном формате `EnterpriseData` (КД 3.1 + подсистема обмена БСП)**. Для транспортного уровня (HTTP/OData/файловые каналы и регистрация планов обмена) сочетай его с [`onec-integration-and-exchange`](../onec-integration-and-exchange/SKILL.md).

## 1. Сначала установи технологию обмена в проекте

В реальных базах 1С параллельно живут оба поколения конвертации — не угадывай архитектуру без проверки метаданных и макетов:

| Признак в исходниках | Поколение | Где лежит логика |
|---|---|---|
| Макет `ПравилаОбмена` (XML с тегами `<ПравилаОбмена>`, `<ПКО>`, `<ПКС>`, `<ПВД>`), обработка `УниверсальныйОбменДаннымиXML` или `КонвертацияОбъектовИнформационныхБаз` | **КД 2 (2.1)** | XML-файл правил + вызовы из подсистемы обмена БСП (`ОбменДаннымиСервер`) |
| Пакеты XDTO `EnterpriseData_*`, общий модуль менеджера обмена (`ОбменДаннымиXDTOСервер`, `МенеджерОбменаЧерезУниверсальныйФормат`), процедуры `ПриОтправкеДанныхПотребителю` / `ПриПолученииДанныхОтКорреспондента` | **КД 3 / EnterpriseData** | BSL-код общего модуля менеджера обмена внутри самой конфигурации (или расширения) |

## 2. Инварианты и ловушки КД 2 (XML-правила `ПВД` / `ПКО` / `ПКС`)

### Поиск объектов и защита от дублей / затирания НСИ
1. **Поиск по внутреннему УИД vs по полям поиска**:
   - Если `ИскатьОбъектПриЗагрузкеПоВнутреннемуИдентификатору` включён, но базы создавались независимо (не распределённая ИБ и без первичной синхронизации УИД), одинаковая номенклатура или контрагент имеют разные `УникальныйИдентификатор()`. Задай детерминированные **поля поиска** (`ИНН` + `КПП` для юрлиц, `Артикул` / `Код` / внешний ключ сопоставления) и порядок вариантов поиска (`НомерВариантаПоиска`).
   - Никогда не используй одно только `Наименование` как единственное поле поиска для справочников с омонимами или редактируемыми названиями.
2. **Классическая авария КД 2 — затирание существующего справочника при выгрузке по ссылке**:
   - Когда документ выгружает контрагента или номенклатуру **по ссылке** с урезанным набором ПКС (только поля поиска), а флаг ПКО **«Не замещать существующие объекты при загрузке»** (`НеЗамещать`) выключен, приёмник находит карточку НСИ и **обнуляет непереданные реквизиты или табличные части**!
   - Разделяй полное ПКО для прямой выгрузки НСИ и ссылочное ПКО (`СвойстваПоиска` + запрет перезаписи существующего объекта при загрузке по ссылке) либо включай `НеЗамещать` для ссылочной синхронизации.

### Порядок обработчиков событий КД 2 и передача данных
Не путай контекст переменных на стороне источника и приёмника:

| Этап | Событие | Ключевые переменные и ограничения |
|---|---|---|
| Выгрузка выборки | `ПВД.ПередОбработкой` / `ПриВыгрузке` | Формирование `ВыборкаДанных` или обход коллекции; для каждого элемента вызывается `ВыгрузитьПоПравилу(Источник, , ВходящиеДанные, , ИмяПКО)`. |
| Выгрузка объекта | `ПКО.ПередВыгрузкой` | Доступен `Источник`, можно установить `Отказ = Истина` или подготовить `ВходящиеДанные` (`Структура`) для дочерних ПКС. |
| Выгрузка свойства | `ПКС.ПередВыгрузкой` / `ПриВыгрузке` | Если источник ПКС не совпадает с реквизитом `Источника`, заполняй `Значение` в `ПриВыгрузке` либо помечай получение из `ВходящиеДанные`. При пустом `Источник` и отсутствии кода ПКС не выгрузит ссылочный узел. |
| Загрузка в приёмнике | `ПКО.ПриЗагрузке` → `ПослеЗагрузки` | В `ПриЗагрузке` ссылка нового объекта может ещё не быть записана в БД; заполнение зависимых регистров сведений или подчинённых объектов по ссылке выполняй в `ПослеЗагрузки`, когда `Объект` уже имеет `Ссылка` (или управляй `ПараметрыОбъекта`). |

- **Передача служебных реквизитов между источником и приёмником**: если в приёмнике нет прямого реквизита, передавай значение через **параметр ПКС → `ПараметрыОбъекта`** (флаг передачи в параметр на ПКС), чтобы прочитать его в `ПКО.ПослеЗагрузки` через `ПараметрыОбъекта["..."]`.
- **Движения документов в КД 2**: не выгружай одновременно и проведение документа в приёмнике, и его наборы записей регистров по тем же регистраторам без согласованного режима `РежимЗаписи = Запись` — иначе проведение приёмника перезапишет загруженные движения или удвоит остатки.

## 3. Инварианты КД 3 и универсального формата `EnterpriseData`

В современном обмене БСП конвертация исполняется BSL-модулем менеджера обмена внутри конфигурации:

1. **Двустороннее соответствие версий формата (`1.x`)**:
   - Проверь зарегистрированные версии формата в `ПолучитьВерсииФорматаОбмена` на обеих сторонах. Попытка заполнить свойство XDTO, появившееся в более старшей версии `EnterpriseData`, падает с ошибкой валидации схемы XDTO на этапе сериализации.
2. **Сопоставление ссылок (`СведенияОбОбъектахОбменаБСП` / регистр `ПубличныеИдентификаторыСинхронизируемыхОбъектов`)**:
   - Не подменяй публичный идентификатор синхронизации случайным `Новый УникальныйИдентификатор()` при каждой отправке — это плодит дубли при каждом повторном сеансе обмена.
3. **Идемпотентность повторной загрузки документа и табличных частей**:
   - При повторном приходе изменённого документа через `ПриПолученииДанныхОтКорреспондента` очищай и пересобирай перезаполняемые табличные части детерминированно, но сохраняй локальные реквизиты приёмника, которые не входят в состав `EnterpriseData` (например, локального ответственного, комментарий склада или статус согласования в базе-приёмнике!).
4. **Даты запрета загрузки**:
   - Вызовы записи из обмена проходят через проверку дат запрета загрузки для конкретного `УзелОбмена` (см. [`onec-bsp-api`](../onec-bsp-api/SKILL.md)). Не отключай `ОбменДанными.Загрузка = Истина` без понимания последствий: этот признак одновременно управляет подписками БСП и повторной авторегистрацией изменений на узлах плана обмена (защита от «пинг-понга» бесконечной пересылки объекта туда-обратно).

## 4. Чеклист верификации правил обмена

1. **Первичная выгрузка + повторная выгрузка без изменений**: повторный пакет того же объекта не должен создавать дубль справочника/документа, менять сумму/количество или перезатирать локальные поля приёмника.
2. **Ссылочная целостность на границе**: новый элемент НСИ, впервые приехавший по ссылке внутри табличной части документа, корректно создаётся и при последующей полной выгрузке карточки НСИ обогащается, а не дублируется.
3. **Пометка удаления и отмена проведения**: проверь оба перехода (`ПометкаУдаления = Истина` и снятие проведения `Проведен = Ложь`) — в приёмнике движения регистратора должны очищаться, а не зависать «сиротами».
4. **Пакетная проверка через EDT / ИБ**: синтаксис модуля менеджера обмена проверяй через [`edt-mcp-project-local-fix`](../edt-mcp-project-local-fix/SKILL.md), а сквозной сценарий «выгрузка → загрузка → повторная загрузка» — на изолированных файловых базах через [`vanessa-runner`](../vanessa-runner/SKILL.md).
