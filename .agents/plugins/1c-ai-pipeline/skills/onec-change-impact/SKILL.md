# Что затронет изменение решения

Я как аналитик 1С хочу добавить новое поведение и сохранить уже работающие
операции, чтобы получить развитие решения без незаметного изменения учёта.

## От потребности к границе изменения

Установи роль, действие и наблюдаемый результат. Раздели новое требование и
неизменяемые условия: единицы хранения, уже выполненные операции, закрытые
периоды, документ-основание, согласованные правила расчёта. Не превращай
пожелание о новом поведении в выдуманный дефект и не ограничивай результат
перечнем найденных файлов. Учитывай уже данное разрешение на реализацию.

Исследуй подтверждённую основную конфигурацию и применяемые расширения через
доступные инструменты. Проследи конкретную цепочку: пользовательская команда
→ обработчик → общий метод → запись/движение → потребитель данных. Для каждого
звена укажи найденный объект или метод и его роль в требовании.

## Три разных вида зависимости

- Декларативная: тип реквизита, измерение регистра, состав формы. Принадлежность
  одной подсистеме не означает вызов; диаграмма метаданных не доказывает запись.
- Исполняемая: вызов процедуры, запрос, обработка проведения, подписка на событие.
  Для регистра найди все источники записи, включая наборы записей без регистратора.
- Динамическая: строковое имя команды, оповещение, настройка обмена, публичный API,
  внешняя обработка. Нулевой результат статического поиска не исключает использование.

Помечай неподтверждённые связи как предположения. Не заявляй полноту по частичной
выгрузке или нескольким найденным модулям. Проверяй только неопределённость,
которая может изменить решение; не запускай повторное исследование без причины.

## Новое представление или новая модель

Сортировка и отбор изменяют представление, но не должны перепроводить документы
или перераспределять ресурсы. Отдельно проверь общий итог и итог выбранного среза.

Для единиц измерения явно задай направление пересчёта и место округления.
До предложения формулы прочитай производителя и потребителя каждого операнда: количество документа уже может хранить штуки, а потребность регистра — итоговую норму на весь заказ. Название поля не доказывает единицу. Зафиксируй смысл каждого множителя по коду. Умножение готового итога повторно на количество или коэффициент упаковки недопустимо. При неизвестной единице сначала установи её, не придумывай расчёт.
Различай единицу заказа, хранения, расчёта потребности и печати; не меняй
хранимое количество только ради удобной подписи. Проверяй частичную обработку,
неполную упаковку и сохранность уже выполненной части.

Новая аналитика меняет ключ записи, группировку и итог. Установи значение для
существующих данных и поведение пустого значения. Не распределяй старые записи
по новым разрезам без основания. Если требуется переход, сделай повтор команды
безопасным и проверь сохранность количества и связей.

## Реализация и проверяемый результат

В разрешённом объёме измени нужные звенья цепочки, а не все найденные объекты.
Подходящие навыки формы, СКД, расширения и тестирования выбирай по выявленной
задаче. Сохрани стандартные механизмы, где они покрывают потребность.

Проверка вспомогательной функции не заменяет выполнение вызывающей команды.
Проверь новое действие и один существенный сохраняемый сценарий: результат
виден человеку, запись сохраняется, повтор не искажает данные. Отдельно
сообщай вывод из исходников, выполненное изменение и фактический результат
проверки. Не объявляй тест пройденным по наличию feature-файла или фонового запуска.

Итог для аналитика: что стало возможно, какие связанные операции затронуты,
что осталось неизменным и чем это подтверждено. Полезные артефакты — рабочая
форма или отчёт, краткая карта подтверждённых связей и результат проверки.

## Развитие существующего поведения

При разрешённой доработке анализ влияния обслуживает новую возможность, а не становится самостоятельным аудитом. Назови добавленное действие роли и уже существующую договорённость, которую требуется сохранить. Например, новые коммерческие условия действуют на новые заказы, а согласованный заказ содержит собственный снимок. Подтверждение сохранности относится к этому поведению, а не заменяет его демонстрацией тестового инструмента.
