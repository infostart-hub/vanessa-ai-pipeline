# Связи и точечные изменения

## Поля, вычисления и ресурсы

Для поля связать источник и псевдоним полного запроса, конкретный набор,
field/dataPath, тип и точность, роль, ограничения использования,
выборку/группировку/отбор/сортировку/оформление целевых настроек.
Одинаковый dataPath в разных наборах не делает их одним полем.
Автозаполнение доступных полей не доказывает актуальность всех привязок.

Вычисляемое поле имеет выражение и тип, ресурс — выражение агрегации
и область групп. Проверить ссылочные зависимости выражений, точность,
пустые значения, деление на ноль и смысл итогов. Название ресурса не
определяет агрегат. Среднее процентов, сумма остатков и повторная сумма
после соединения требуют обоснования по зерну данных.

Добавление поля набора и добавление его в selection — отдельные решения.
Для вывода выбрать именно нужный уровень: вариант, группа или таблица.
При изменении типа проверить значения, выражения и пользовательские настройки.

## Наборы и связи

Определить тип набора: запрос, объект или объединение. Источник выбирать
по модели и сценарию, а не копировать первый dataSource. Для связи записать
оба набора, выражения ключей, передаваемый параметр, условие и обязательность.
Обосновать кратность: связь один-ко-многим способна размножить ресурсы.
Не придумывать данные для объектного набора по аналогии с запросным.

## Параметры и период

Параметр схемы, &параметр запроса и dataParameters настроек различаются.
Связать имя, объявленный тип, список/скаляр, значения по умолчанию,
доступные значения, выражение, use/useRestriction и пользовательскую
доступность. Неподдержанный тип значения не преобразовывать в строку.

Для периода проверить существующую цепочку: пользовательский период →
выражения начала/окончания → параметры запроса → значения варианта.
StandardPeriod не равен строке LastMonth. Не генерировать скрытую пару дат
по одному шаблонному имени и не заменять настройку StandardPeriod
произвольным ValueSpec. Возможность записи типа проверить по live guide.

Границы периода обосновать для конкретной виртуальной таблицы и сценария.
Не подставлять КонецДня/другую границу без требования и проверки текущего
выражения. Текст запроса может быть валиден при неверной предметной границе.

Переименование требует карты всех ссылок: запросы наборов, выражения
параметров и полей, значения вариантов, отборы и оформление. Похожее имя,
строка и комментарий не являются ссылкой. Не делать глобальную замену
подстроки. Удаление узла требует той же карты потребителей и решения по
каждому; запрещено автоматически чистить только первый найденный отбор.

## Варианты и структура

Имя варианта и его представление — разные значения. settings варианта
и defaultSettings не объединять. Для выбранного варианта прочитать selection,
структуру, фильтры, dataParameters, order, conditionalAppearance,
outputParameters и userFields в объёме затронутых зависимостей.

Структура хранит группировки/таблицы и их дочерние уровни; имя группировки
не заменяет индексный адрес EDT. Для изменения полей группы сохранять
её выборку, сортировку, фильтры, оформление, параметры вывода и дочерние узлы.
Замена всей структуры допустима лишь когда именно вся структура — цель
и доказана сохранность нужного материала. Диаграмму не считать группировкой.

Фильтр определяется областью, позицией и полным условием, а не одним полем.
Различать вложенные AndGroup/OrGroup, сравнение, тип значения и use.
Смена значения/подписи не должна включать отключённый отбор.
Сохранять use=false, viewMode, существующие userSettingID и представления,
если задача их не меняет. Не генерировать новые ID для прежних настроек.
Настройки проектного варианта не доказывают состояние сохранённых настроек
конкретного пользователя информационной базы.

Для сортировки проверить уровень и направление, для selection — порядок
и Auto-элементы. Очистка списка и удаление одной позиции различаются.
Пустые settings-holder могут хранить доступность и идентичность настройки:
не считать их лишними только из-за пустого items.

Для условного оформления связать условия, целевые поля, область применения,
тип и use каждого параметра оформления. Отбор правила и отбор отчёта —
разные области. Имена параметров и допустимые enum брать через dcs options
и актуальный guide. Отдельно учитывать use самого правила и его параметра.
Параметр вывода, макет оформления и шаблон расшифровки — разные сущности;
поддержку последнего не выводить из поддержки outputParameter.

## Передача владельцу EDT

Адреса natural-key узлов выбирать из get. Для ordered-узлов копировать
индексный адрес и root hash того же чтения; экранирование RFC-6901 сохранять.
update меняет существующее, upsert может создать/добавить, replace сбрасывает
непереданные части, remove удаляет один узел. Семантику массивов уточнять
по текущему guide: пустой массив не означает универсальную очистку.

replace/remove и индексные правки требуют expectedHash. Передача hash
не делает серию отдельных вызовов одной транзакцией. После изменения
следующая зависимая запись опирается на свежий get; старый индекс не угадывать.
Отказ инструмента записи фиксируется с сохранением исходной причины.

Неподдержанный дизайнерский материал обозначить адресом и причиной.
Штатный lossless XML канал dcs может быть отдельно выбран для задачи,
которая изначально требует полного переноса схемы; это не запасная правка
файла после отказа структурированной записи. Он требует полного документа,
согласованных страниц и hash назначения. Не переходить на него молча
при точечном изменении и не отбрасывать диаграммы ради принятия body.

## Пример разбора

Отчёт имеет два варианта: таблицу по товару и диаграмму по получателю.
Задача меняет подпись суммы в таблице. Выбрать точный табличный вариант,
проверить, берётся ли подпись из общего поля или selection этого варианта,
и предложить изменение в требуемой области. Общая подпись может затронуть
оба варианта. Замена всей структуры не нужна; диаграмма сохраняется.
Отключённый отбор организации остаётся отключённым. Если текущий контракт
не выражает нужное изменение, вернуть ограничение, а не расширять задачу.
