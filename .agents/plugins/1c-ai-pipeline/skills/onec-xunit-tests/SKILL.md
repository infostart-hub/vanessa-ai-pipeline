# Тесты xUnit (Vanessa-ADD)

Используй навык, когда результат доказывается модульным или дымовым тестом Vanessa-ADD (xUnit): внешняя обработка с набором тестов, без UI-сценария Gherkin.

Навык описывает, как писать и регистрировать тесты. Прогон выполняет исполнитель, выбранный проектом для Vanessa-ADD xUnit. Сценарии Vanessa Automation — навык `onec-vanessa-scenario`. Модульные тесты YAxUnit в расширении — `onec-yaxunit-tests`.

## Где живут тесты

- Тест — **модуль объекта внешней обработки**, не файл `.os`. Файл `.os` с `&Тест` относится к OneScript (OneUnit / 1testrunner) и к этому навыку не принадлежит.
- Исходники обычно лежат в каталоге вроде `tests/epf/<Имя>/` (выгрузка конфигуратора или проект EDT). Перед прогоном обработка собирается в `.epf`; в git остаётся исходник.
- Дымовые обработки пакета add лежат отдельно (часто в каталоге smoke установленного add). Не копируй их каркас в свой модуль и не подменяй путь к своим тестам дымовым набором.

## Модуль объекта

```bsl
Перем КонтекстЯдра;
Перем Утверждения;

Процедура Инициализация(КонтекстЯдраПараметр) Экспорт
	КонтекстЯдра = КонтекстЯдраПараметр;
	Утверждения = КонтекстЯдра.Плагин("БазовыеУтверждения");
КонецПроцедуры

Процедура ЗаполнитьНаборТестов(НаборТестов, КонтекстЯдраПараметр) Экспорт
	КонтекстЯдра = КонтекстЯдраПараметр;
	НаборТестов.Добавить("ПроверитьСложениеЧисел");
КонецПроцедуры

Процедура ПроверитьСложениеЧисел() Экспорт
	Утверждения.ПроверитьРавенство(2 + 2, 4, "Сложение целых чисел");
КонецПроцедуры
```

- Загрузчик сначала вызывает `ЗаполнитьНаборТестов` с двумя аргументами и при лишнем параметре повторяет вызов с одним `НаборТестов`. Оба вида встречаются в чужих обработках.
- `ПолучитьСписокТестов` без параметров — запасной путь, если первого метода нет. Сигнатура с аргументом вроде `ЮнитТестирование` отвергается.
- `ПолучитьСписокТестов(КонтекстФреймворкаBDD)` в `step_definitions` — шаги Vanessa, не тест xUnit.
- Имя в наборе совпадает с экспортной процедурой. Префикс `Тест` или `ТестДолжен_` не нужен: раннер вызывает имя как есть. В дымовых обработках add встречаются и `Fact_`, и `Тест_`, и `ТестДолжен_`.

## Утверждения

- Плагин `БазовыеУтверждения`: `ПроверитьРавенство(Первое, Второе, Пояснение)` — первым выражение, вторым эталон. Того же плагина достаточно для `ПроверитьИстину`, `ПроверитьЛожь`, `ПроверитьЗаполненность`, `ПроверитьТип`, `ПроверитьВхождение`.
- Если в модуле уже `УтвержденияBDD` и `Ожидаем.Что`, не переписывай проверки на `ПроверитьРавенство`.

## Настройки и доказательство

- Путь к собранным `.epf` передаётся исполнителю прогона как каталог или файл тестов. Файл параметров xUnit (часто `tools/xUnitParams.json`) задаёт настройки прогона, не каталог своих тестов: ключей, которых в файле нет, не добавляй.
- Запускается обработка целиком, не один метод. Версию runner и формат отчёта сверяй с контрактом проекта; устаревшие и актуальные опции отчёта не смешивай наугад.
- Одна информационная база — один владелец прогона. Независимые прогоны не пересекаются. Проверка конкурентности может использовать несколько согласованных сеансов внутри одного прогона, только если штатный исполнитель поддерживает такой сценарий. Последовательные вызовы и моки не доказывают отсутствие гонки. Завершение определяй по квитанции и владению процессами, а не только по открытому окну; чужие сеансы не завершай.
- Сначала подтверди, что Vanessa-ADD и способ прогона есть в проекте. Если движка или исполнителя нет, остановись: установка — решение владельца стенда. Успех — квитанция прогона с выполненным тестом, не наличие модуля обработки.
