# Обновление версии ИБ и конфигурации

Карта для подсистем ОбновлениеВерсииИБ и ОбновлениеКонфигурации: регистрация обработчиков миграции, запись данных внутри обработчика, версии подсистем, блокировка формы до отложенного обновления. Имена и регионы подтверждены для БСП 3.1.11. Для целевого проекта сверяй модуль, сигнатуру и регион по модели EDT.

## Модули

| Модуль | Роль |
|---|---|
| ОбновлениеИнформационнойБазы | Стабильный серверный API: обработчики, обёртки записи, версии ИБ, ход обновления |
| ОбновлениеИнформационнойБазыКлиент | Формы отложенных обработчиков, индикация, интерактивный запуск |
| ОбновлениеИнформационнойБазыВызовСервера | Серверный вызов с клиента без контекста формы |
| ОбновлениеИнформационнойБазыПереопределяемый | Серверные хуки: БСП вызывает, конфигурация реализует |
| ОбновлениеИнформационнойБазыКлиентПереопределяемый | Клиентские хуки возможности обновления и описания изменений |
| ОбновлениеИнформационнойБазыСлужебный и служебные суффиксы | Служебный API; из прикладного кода не вызывай |
| ОбновлениеКонфигурации, ОбновлениеКонфигурацииКлиент | Отдельная подсистема: патчи и интерактивная установка обновлений |

Не существуют: общий модуль ОбновлениеИнформационнойБазыСервер. Серверные обёртки записи лежат в ОбновлениеИнформационнойБазы без суффикса. Полные имена сверяй по этому списку, а не достраивай по аналогии с другими подсистемами.

## Регистрация обработчика

- Прикладные обработчики регистрирует ПриДобавленииОбработчиковОбновления прикладного модуля вида ОбновлениеИнформационнойБазыБП или ОбновлениеИнформационнойБазыУТ. Одноимённый метод ОбновлениеИнформационнойБазыСлужебный — внутренний крючок БСП, не место для прикладной миграции.
- Колонки таблицы: Версия (номер, `*` при каждом обновлении, пустая при НачальноеЗаполнение), Процедура (полное имя экспортной процедуры), РежимВыполнения (`Монопольно`, `Оперативно`, `Отложенно`). Для отложенного нужны Идентификатор, БлокируемыеОбъекты и ПроцедураПроверки.
- Таблицу колонок даёт ОбновлениеИнформационнойБазы.НоваяТаблицаОбработчиковОбновления.

## Запись внутри обработчика

- В обработчике пиши только обёртками ОбновлениеИнформационнойБазы.ЗаписатьДанные, ЗаписатьОбъект, ЗаписатьНаборЗаписей, УдалитьДанные. Прямой Объект.Записать() включает бизнес-логику и регистрацию на планах обмена.
- По умолчанию ВключитьБизнесЛогику = Ложь, регистрация на узлах планов обмена не выполняется. Включай бизнес-логику только когда миграция осознанно проводит документ или должна уйти в обмен.
- Эти обёртки только для кода миграции. Вне обработчика обновления пользовательская запись — обычный Объект.Записать() со всей логикой.
- Контекст обработчика проверяет ЭтоВызовИзОбработчикаОбновления.

## Версии, ход и блокировка формы

- ВерсияИБ / УстановитьВерсиюИБ: третий параметр ЭтоОсновнаяКонфигурация обязателен; без него версия уйдёт в библиотечную ветку. Для основной конфигурации идентификатор — Метаданные.Имя.
- ЗарегистрироватьНовуюПодсистему помечает подсистему актуальной без обработчиков начального заполнения; вызывай из хука ПередОбновлениемИнформационнойБазы.
- Необходимость и ход: НеобходимоОбновлениеИнформационнойБазы, ВыполняетсяОбновлениеИнформационнойБазы, ОтложенноеОбновлениеЗавершено, ПерезапуститьОтложенноеОбновление.
- В форме объекта до изменения: МетаданныеИОтборПоДанным, затем ДанныеОбновленыНаНовуюВерсиюПрограммы. Ложь — объект ещё в отложенном обновлении; нестандартную проверку даёт хук ПриВыполненииПроверкиОбъектОбработан.
- Пакетный запуск: сначала ОбновлениеКонфигурации.ИсправленияИзменены, затем ОбновлениеИнформационнойБазы.ВыполнитьОбновлениеИнформационнойБазы. Интерактивная установка — через ОбновлениеКонфигурацииКлиент, не через ВызовСервера при работающих пользователях.

## Первый запуск прикладного решения на поставке БСП

- Поставка библиотеки не является готовым прикладным решением. Зарегистрируй основную конфигурацию через предусмотренные этой версией точки подключения; не удаляй проверку, которая сообщает о неподготовленной поставке.
- В БСП 3.1.12 фоновое обновление параметров запускается без расширений. Регистрация основной конфигурации только в расширении не подходит: интерактивный старт может пройти, а начальное заполнение упасть.
- Загрузка конфигурации и изменение свойств расширения не подтверждают завершение начального заполнения. Перед Vanessa с отдельным TestClient выполни штатный запуск `ВыполнитьОбновлениеИЗавершитьРаботу` и дождись его завершения. Подтверди успешное обновление в журнале. Иначе второй сеанс может получить запрет входа, пока первый выполняет обновление.
- Если при переносе собственного модуля из расширения в основную конфигурацию сохранился его внутренний идентификатор, удали ставшую ненужной копию из расширения и его состава метаданных. Не оставляй два собственных объекта с одним идентификатором. Согласуй исходники EDT и развёртываемую выгрузку.
