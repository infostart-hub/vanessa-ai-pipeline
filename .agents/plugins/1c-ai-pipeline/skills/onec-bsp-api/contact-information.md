# Контактная информация и адреса

Карта для подсистем КонтактнаяИнформация, АдресныйКлассификатор и РаботаСАдресами. Имена и регионы подтверждены для БСП 3.1.11. Для целевого проекта сверяй модуль, сигнатуру и регион по модели EDT; собственные справочники адресов конфигурации эта карта не описывает.

## Модули

| Модуль | Роль |
|---|---|
| УправлениеКонтактнойИнформацией | Стабильный серверный API чтения, записи, видов и представления |
| УправлениеКонтактнойИнформациейКлиент | Формы ввода и команды |
| УправлениеКонтактнойИнформациейКлиентСервер | Детекторы формата и заполненности |
| УправлениеКонтактнойИнформациейПереопределяемый | Хуки настроек и начального заполнения |
| АдресныйКлассификатор | Проверка адресов, коды регионов, ОКТМО |
| РаботаСАдресами | Разбор адреса на поля, сборка по идентификатору ФИАС |

Не существуют: УправлениеКонтактнойИнформациейСлужебныйКлиент и …СлужебныйКлиентСервер, РаботаСАдресамиСлужебный без суффикса, методы ПолучитьКонтактнуюИнформацию и УстановитьКонтактнуюИнформацию. Методы ПриОпределенииТипаКонтактнойИнформации и подобные в модулях Локализация — не прикладные хуки.

## Хранение и чтение

- Контактная информация хранится в табличной части КонтактнаяИнформация владельца; значение — JSON БСП, старые записи бывают в XML. Отдельные строковые реквизиты в обход табличной части теряют проверки и историю.
- КонтактнаяИнформацияОбъекта(Владелец, ВидИлиТип, Дата, ТолькоПредставление): при ТолькоПредставление = Истина (по умолчанию) возвращается строка, а не таблица. Для значений передай Ложь.
- Для множества владельцев используй КонтактнаяИнформацияОбъектов(Массив, Типы, Виды, Дата) одним запросом вместо вызова в цикле.
- Строку для формы или печати даёт ПредставлениеКонтактнойИнформацииОбъекта; JSON в макет не подставляй.
- Вид по имени — ВидКонтактнойИнформацииПоИмени.

## Запись

- ЗаписатьКонтактнуюИнформацию(Объект, Значение, Вид, Тип, ИдентификаторСтроки, Дата) — процедура, принимает объект, а не ссылку; после неё объект записывают.
- УстановитьКонтактнуюИнформациюОбъекта(СсылкаИлиОбъект, Таблица, Замещать) с таблицей из НоваяКонтактнаяИнформация сама записывает владельца, если передана ссылка.
- ДобавитьКонтактнуюИнформацию добавляет значение по представлению с распознаванием адреса.

## Разбор и сравнение адресов

- Перед разбором проверь формат: УправлениеКонтактнойИнформациейКлиентСервер.ЭтоКонтактнаяИнформацияВJSON / ЭтоКонтактнаяИнформацияВXML.
- Поля адреса даёт РаботаСАдресами.СведенияОбАдресе; одноимённый метод УправлениеКонтактнойИнформацией.СведенияОбАдресе имеет другую сигнатуру — уточняй модуль. Ручной разбор JSON ломается при изменении формата БСП.
- Сравнение адресов на совпадение строй по разобранным полям или кодам адреса (АдресныйКлассификатор.КодыАдреса), а не по строке представления. Правило «что считать дублем адреса» — продуктовое решение задачи; зафиксируй его в спецификации.
- АдресныйКлассификатор.ПроверитьАдреса и АдресныйКлассификаторЗагружен обращаются к веб-сервису и долго выполняются; вызывай фоном. РаботаСАдресами.ПроверитьАдреса — другой метод.
- КодРегионаПоНаименованию находит субъект РФ, включая города федерального значения; для населённого пункта, не являющегося субъектом, используй СведенияПоОКМТО или СведенияОбАдресе.
