# Выбор API и точек расширения БСП

Используй навык, когда решение задачи зависит от Библиотеки стандартных подсистем 1С: выбор общего модуля или метода, вызов на клиенте/сервере, расширение поведения, проверка устойчивости API.

Навык описывает предметные различия. Состояние конфигурации и структурированные изменения выполняются через EDT MCP и соответствующие предметные навыки.

## Сначала установи версию и наличие БСП

БСП не предполагай по наличию BSL-кода, общих модулей или сходству имён. Установи точный проект EDT и доступные сведения о конфигурации. Если модель EDT не подтверждает наличие и версию БСП, скажи, что вызов не проверен для этого проекта. Не переключайся на XML-выгрузку после отказа EDT; это отдельный источник фактов, допустимый только когда пользователь явно выбрал такую выгрузку.

Подробности ниже подтверждены для БСП 3.1.11. Для другой версии используй их только как карту понятий: имя модуля, сигнатуру, регион, свойства общего модуля и совместимость сверяй с исходниками или документацией именно этой версии. Не показывай пример 3.1.11 как проверенный вызов иной версии.

## Выбери подсистему и полный модуль

### Поставка библиотеки — ещё не прикладная база

При подготовке нового стенда отличай исходники поставки БСП от конфигурации, в которую БСП уже внедрена. Успешная загрузка XML или расширения не подтверждает запуск приложения. Сообщение «Файл поставки ... не предназначен для создания информационных баз по шаблону» означает отсутствие регистрации прикладной конфигурации, а не запрос доверия внешней обработке. Не повторяй запуск и не отключай эту проверку. Используй предусмотренную версией точку `ПодсистемыКонфигурацииПереопределяемый.ПриДобавленииПодсистем`: зарегистрируй серверный модуль приложения с его именем, версией, зависимостью от БСП и обработчиками обновления. После подключения выполни штатное начальное заполнение. Проверки совместимости БСП сохраняй.

У общих модулей БСП нет общего префикса БСП_. Имя обычно связано с предметной подсистемой: например, УправлениеПечатью, Пользователи, АдресныйКлассификатор. Найди модуль по назначению подсистемы, затем укажи его полное имя. Не придумывай варианты по аналогии.

Суффиксы помогают понять назначение модуля, но окончательную конфигурацию задают свойства самого общего модуля:

| Признак | Значение |
|---|---|
| без суффикса | Обычно серверный контекст |
| Клиент | Клиентский код |
| КлиентСервер | Общий код клиента и сервера; не обращается напрямую к базе |
| ВызовСервера | Серверный модуль, метод которого может вызвать клиент; исполнение остаётся на сервере и вне контекста формы |
| Служебный | Внутренний API; совместимость не гарантируется |
| ПовтИсп | Кэширование возвращаемого значения; длительность определяется свойством модуля |
| Переопределяемый | Точка расширения: БСП вызывает метод, прикладная конфигурация реализует его |
| Глобальный | Доступность по короткому имени; контекст исполнения всё равно определяется свойствами модуля |
| РФ, Локализация | Региональный или языковой вариант |

Суффиксы могут сочетаться. Инициатор вызова и место исполнения — разные факты: ВызовСервера не означает клиентское исполнение. Не считай Экспорт или разрешение серверного вызова доказательством стабильности.

## Определи, что именно перед тобой

Проверяй регион метода и роль модуля отдельно:

| Регион | Прикладное использование |
|---|---|
| ПрограммныйИнтерфейс | Основной публичный API; стабильность заявляй только для подтверждённой версии БСП |
| СлужебныйПрограммныйИнтерфейс | Служебный API, обратная совместимость не гарантируется; выбирай лишь при отсутствии публичного аналога и отмечай риск |
| СлужебныеПроцедурыИФункции | Внутренняя реализация, не вызывай из прикладного кода |
| УстаревшиеПроцедурыИФункции | Устаревший API; для нового кода ищи публичную замену |
| прочие внутренние регионы | Не считай прикладным API без явного подтверждения назначения |

Модуль Переопределяемый — не обычная библиотека функций. БСП вызывает описанный в нём хук; прикладной код реализует его в своей конфигурации по правилам этой версии. Не предлагай вызвать такой метод как Модуль.Метод(...). Это остаётся хуком, даже если регион называется ПрограммныйИнтерфейс: регион и роль — независимые классификации.

## Не принимай похожее имя за факт

Для БСП 3.1.11 проверены частые ошибки:

- ОбщегоНазначенияСлужебный без дополнительного суффикса отсутствует; встречаются ОбщегоНазначенияСлужебныйКлиент и ОбщегоНазначенияСлужебныйКлиентСервер.
- РегламентныеЗадания — подсистема, а не общий модуль; серверный общий модуль называется РегламентныеЗаданияСервер.
- БизнесПроцессыИЗадачи без суффикса отсутствует; серверный модуль — БизнесПроцессыИЗадачиСервер.
- БезопасноеХранилище — не общий модуль; в БСП 3.1.11 это регистр БезопасноеХранилищеДанных, работа с которым выполняется через публичные методы общего модуля ОбщегоНазначения.

Используй эти примеры только в границе версии 3.1.11. При другой версии перепроверь каждый факт.

Регистрация основной прикладной конфигурации должна находиться в основной конфигурации, а не только в расширении. В БСП 3.1.12 обновление параметров работы программы запускается с `БезРасширений = Истина`; регистрация из расширения может пройти интерактивный старт, но исчезнуть в фоновом начальном заполнении. Не отключай этот режим фоновой операции ради обхода ошибки. Проверяй завершение начального заполнения, а не только появление рабочего стола или индикатора прогресса.

Если журнал сообщает «расширение модуля запрещено ... подключено в безопасном режиме», перехват не исполнялся. Настройка свойств расширения после обычного старта не поможет, если старт падает раньше. Для разрешённой служебной настройки используй предусмотренный БСП режим `ОтключитьЛогикуНачалаРаботыСистемы`, получи результат изменения свойств от обработчика, затем верни обычный запуск. Служебный режим не является готовым пользовательским результатом и не заменяет регистрацию основной конфигурации.

## Перед ответом или предложением изменения

При подключении истории изменений в БСП 3.1.12 проверь оба определяемых типа:
ссылочный `ВерсионируемыеДанные` и объектный `ВерсионируемыеДанныеОбъект`.
Подписка `ЗаписатьВерсиюОбъекта` получает источник из объектного типа.
Настройка версионирования и доступная кнопка истории сами по себе не доказывают,
что запись версий подключена. Выполни реальные изменения реквизитов под именованным
пользователем и проверь версии, автора и время в штатной истории. Пустая открытая
форма не является успешным результатом. Учитывай, что история появляется после
подключения механизма, а не восстанавливает прежние изменения задним числом.

1. Зафиксируй проект, наличие и версию БСП по доступным фактам.
2. Назови полное имя модуля и метод; укажи контекст исполнения и объясни, кто вызывает код — приложение или сама БСП.
3. Различи стабильный публичный вызов, служебный/устаревший метод, внутреннюю процедуру и хук. Не выводи статус API только из Экспорт.
4. Если метод, версия, регион или свойства модуля не подтверждены, обозначь конкретный неизвестный факт и не выдавай предполагаемую сигнатуру за проверенную.
5. Для хука опиши, где приложение реализует расширение; не давай пример прямого вызова.
6. Если проект доступен через EDT MCP, прочитай фактический прикладной обработчик и форму сам. Не проси пользователя прислать доступный код и не подменяй исследование конкретного объекта общими советами или предполагаемой сигнатурой.

Существующая EDT-модель — источник фактов для выбранного проекта. Используй только штатные возможности и руководства edt-mcp. Не добавляй отдельный экспортный парсер, CLI, исполнитель, hook или маршрут задачи в этот навык.
