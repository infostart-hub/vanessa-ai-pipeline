# Бизнес-процессы и задачи исполнителей

Карта для подсистемы БизнесПроцессыИЗадачи: выполнение, принятие и перенаправление задач, остановка процессов, форма выполнения, контроль сроков. Имена и регионы подтверждены для БСП 3.1.11. Для целевого проекта сверяй модуль, сигнатуру и регион по модели EDT; прикладные бизнес-процессы, формы списков и виджеты конфигурации эта карта не описывает.

## Модули

| Модуль | Роль |
|---|---|
| БизнесПроцессыИЗадачиСервер | Стабильный серверный API |
| БизнесПроцессыИЗадачиКлиент | Стабильный клиентский API: открывает формы, задаёт вопросы пользователю |
| БизнесПроцессыИЗадачиКлиентСервер | Общий код без обращения к базе |
| БизнесПроцессыИЗадачиВызовСервера | Служебный; методы-дублёры в служебном и устаревшем регионах, из прикладного кода не вызывай |
| БизнесПроцессыИЗадачиПереопределяемый | Серверные хуки: БСП вызывает, конфигурация реализует |
| БизнесПроцессыИЗадачиКлиентПереопределяемый | Клиентский хук ПриВыбореИсполнителя |

Не существуют: общий модуль БизнесПроцессыИЗадачи без суффикса (это имя подсистемы и определяемого типа), методы ФормированиеЗадач, СоздатьЗадачу в модуле Сервер и ОткрытьФормуЗадачи в модуле Клиент. Задачу создаёт код самого бизнес-процесса; для открытия задачи используют ОткрытьЗначение или параметры из ФормаВыполненияЗадачи.

## Адресация и принятие задачи

- Задача ЗадачаИсполнителя адресуется реквизитами Исполнитель, РольИсполнителя, ОсновнойОбъектАдресации, ДополнительныйОбъектАдресации. Задача роли и задача конкретному исполнителю попадают в разные выборки.
- ПринятьЗадачиКИсполнению(Задачи) и ОтменитьПринятиеЗадачКИсполнению(Задачи) серверного модуля принимают массив задач и вопросов не задают. Клиентские обёртки с теми же именами работают с массивом; вариант с формой дополнительно спрашивает подтверждение.
- Принятие фиксирует, что исполнитель взял задачу в работу, и может изменить её реквизиты адресации и признаки. Что именно меняется, проверь по коду метода в модели EDT своей версии.
- Если задача пропадает из списка или виджета после принятия, сначала найди в EDT запрос динамического списка, отборы и условия формы, которые этот список строят. Сравни их с реквизитами, которые изменило принятие. Не исправляй это обходом принятия и не дублируй задачу.
- Для отображения ответственного используй ИсполнительСтрокой(Исполнитель, РольИсполнителя, ОсновнойОбъектАдресации, ДополнительныйОбъектАдресации): задача роли не всегда имеет конкретного исполнителя.

## Действия с задачами и процессами

- ВыполнитьЗадачу(ЗадачаСсылка, ДействиеПоУмолчанию = Ложь): без Истина выполняется только стандартная отметка, а ОбработкаВыполненияПоУмолчанию бизнес-процесса не вызывается.
- ПеренаправитьЗадачи(Задачи, ИнфоОПеренаправлении, ТолькоПроверка, ПеренаправленныеЗадачи): сначала вызов с ТолькоПроверка = Истина, затем выполнение. Выходной массив может быть короче исходного. Клиентский ПеренаправитьЗадачи открывает форму и не заменяет серверный программный вызов.
- ОстановитьБизнесПроцесс / СделатьАктивнымБизнесПроцесс и пакетные варианты принимают ОпределяемыйТип.БизнесПроцесс. Из формы объекта используй клиентские обёртки: они проверяют права через ПриПроверкеПравНаОстановкуБизнесПроцесса.
- ФормаВыполненияЗадачи(ЗадачаСсылка) возвращает параметры формы, которые задаёт хук ПриПолученииФормыВыполненияЗадачи. Прямое открытие формы объекта задачи обходит этот хук.
- ЗаблокироватьЗадачи / ЗаблокироватьБизнесПроцессы — для изменения в транзакции.
- ПроконтролироватьЗадачи и УведомитьИсполнителейОНовыхЗадачах — обработчики регламентных заданий МониторингЗадач и УведомлениеИсполнителейОНовыхЗадачах. Они рассылают почту и не подходят для интерактивного вызова.
