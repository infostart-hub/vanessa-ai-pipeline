# Пользователи и управление доступом

Карта для подсистем Пользователи, ВнешниеПользователи и УправлениеДоступом: пользователь сеанса, роли, ограничения на уровне записей и права на объекты. Имена и регионы подтверждены для БСП 3.1.11. Для целевого проекта сверяй модуль, сигнатуру и регион по модели EDT.

## Модули

| Модуль | Роль |
|---|---|
| Пользователи | Стабильный серверный API |
| ПользователиКлиент | Стабильный клиентский API только для текущего пользователя |
| ПользователиКлиентСервер | Устаревший целиком; не используй в новом коде |
| ВнешниеПользователи | Стабильный серверный API внешних пользователей |
| УправлениеДоступом | Стабильный серверный API RLS, прав и профилей |
| УправлениеДоступомПереопределяемый, ПользователиПереопределяемый | Хуки: БСП вызывает, конфигурация реализует |

## Выбор метода

- Ссылка пользователя сеанса: АвторизованныйПользователь возвращает пользователя или внешнего пользователя. ТекущийПользователь возвращает только Пользователи и вызывает исключение в сеансе внешнего пользователя. Строка ИмяПользователя() не заменяет ссылку.
- Внешний пользователь: сначала ЭтоСеансВнешнегоПользователя, затем ВнешниеПользователи.ТекущийВнешнийПользователь; объект авторизации — ПолучитьОбъектАвторизацииВнешнегоПользователя.
- Роли: Пользователи.РолиДоступны принимает строку имён через запятую, не массив; ЭтоПолноправныйПользователь учитывает полноправность и привилегированный режим, в отличие от платформенного РольДоступна. Клиентский вариант проверяет только текущего пользователя.
- RLS: УправлениеДоступом.ЧтениеРазрешено / ИзменениеРазрешено возвращают Булево, ПроверитьЧтениеРазрешено / ПроверитьИзменениеРазрешено вызывают исключение. В стандартном варианте (ПроизводительныйВариант() = Ложь) передача пользователя, отличного от текущего, вызывает исключение. Включено ли RLS — ОграничиватьДоступНаУровнеЗаписей().
- Права на объект: ЕстьПраво(Право, СсылкаНаОбъект, Пользователь) принимает ссылку на объект-владелец прав, а не метаданные; имя права задаёт хук ПриЗаполненииВозможныхПравДляНастройкиПравОбъектов. ЕстьРоль проверяет роль через профили групп доступа с учётом RLS на чтение; голую роль конфигурации проверяет РолиДоступны.
- Назначение прав: ВключитьПрофильПользователю / ВыключитьПрофильПользователю — упрощённый режим с персональной группой доступа; УстановитьПраваПользователя — полная переустановка групп.
- После изменения данных, влияющих на доступ, наборы значений доступа обновляет ОбновитьНаборыЗначенийДоступа.

## Диагностика доступа

Применяй, когда пользователь не видит запись, видит чужие записи или получает отказ.

- Раздели два факта: функциональные права (роли, которые пользователь получает через профили групп доступа) и ограничения на уровне записей (виды и значения доступа групп доступа). Роль разрешает действие с объектом, ограничение отбирает строки. Проверяй их отдельно.
- Наличие роли или профиля не доказывает конкретного разрешения. Состав прав роли на объект и текст ограничения доступа читай в модели EDT.
- Пропавшая из списка запись не обязательно вопрос доступа. Сначала исключи отбор и запрос динамического списка и изменение реквизитов самой записи.
- Сравни с контрольным пользователем, у которого поведение правильное. Первая гипотеза — разница их профилей, групп доступа и значений доступа. Каждое отличие отнеси к возможной причине, к требующему доказательства механизма или к шуму.
- Построй матрицу «операция → необходимое право»: открыть, создать, изменить, провести или выполнить, открыть отчёт. Запрещённая операция должна завершиться отказом.
- Проверяй под тестовым пользователем с целевым набором профилей. Успех под «Полные права» или в привилегированном режиме не доказывает исправление.
- Не устраняй ошибку доступа выдачей «Полные права» и привилегированным режимом.
- Сначала исчерпай типовые механизмы: поставляемые профили, группы и значения доступа, хуки УправлениеДоступомПереопределяемый. Правку ролей и ограничений типовой конфигурации оформляй через расширение.
- Массовое снятие ролей — только с тестовым сценарием и планом отката.
- Вывод называет право или ограничение, которое даёт поведение; чем обеспечена рабочая операция; что остаётся запрещённым; как проверить и откатить изменение.
