# ЭП и МЧД, защита ПДн, обмен данными, области данных и локализация БСП

Карта дополнительных подсистем Библиотеки стандартных подсистем (ориентиры имён приведены для БСП 3.1.11+; в целевом проекте всегда сверяй фактический состав и сигнатуры общих модулей через EDT MCP).

## 1. Электронная подпись (ЭП), криптография и МЧД

| Модуль / подсистема | Назначение и контекст |
|---|---|
| `ЭлектроннаяПодписьКлиент` | Интерактивный выбор сертификата, ввод пароля ключевого контейнера и подписание на рабочем месте (КриптоПро CSP / внешняя компонента БСП) |
| `ЭлектроннаяПодпись` | Серверная проверка сохранённых подписей, чтение реквизитов сертификата, привязка к карточке объекта или файлу |
| `ЭлектроннаяПодписьПереопределяемый` | Хуки регистрации типов подписываемых объектов и пользовательских проверок полномочий |
| Подсистема `МашиночитаемыеДоверенности` (в конфигурациях с БЭД / БСП) | Хранение, регистрация в реестре ФНС, проверка срока действия и полномочий представителя по МЧД (формат `003`) |

- **Ловушка клиент/серверного подписания**: закрытый ключ сертификата сотрудника почти всегда находится на клиентском токене/рабочем месте, поэтому интерактивное подписание выполняется асинхронными методами `ЭлектроннаяПодписьКлиент`, а не из серверного фонового задания (серверное подписание возможно только при настроенном серверном криптопровайдере / DSS и обезличенном сертификате системы).
- При проверке подписи физического лица от имени организации проверяй связку сертификата с действующей **МЧД** (совпадение ИНН доверителя, СНИЛС/ИНН подписанта и неистёкший срок доверенности).

## 2. Защита персональных данных (152-ФЗ) и маскирование тестовых баз

- Подсистема `ЗащитаПерсональныхДанных` управляет регистрацией событий доступа к ПДн, согласиями субъектов ПДн и регламентным обезличиванием / уничтожением ПДн по истечении сроков хранения.
- В переопределяемых модулях подсистемы регистрируются предметные виды сведений (ФИО, паспортные данные, СНИЛС, ИНН физлица, телефоны, адреса, банковские счета).
- **Безопасность при передаче выборок и разворачивании копий ИБ**: не выгружай реальные персональные данные из копий продуктивных баз в отчёты диагностики или промпты без псевдонимизации (токенизации ФИО, ИНН, телефонов и номеров счетов).

## 3. Библиотечный обмен данными (`ОбменДанными`)

| Модуль | Роль |
|---|---|
| `ОбменДаннымиСервер` | Запуск сценариев обмена, чтение/запись сообщений плана обмена, работа с регистрацией изменений |
| `ОбменДаннымиСобытия` | Подписки регистрации изменений объектов и наборов записей регистров на узлах планов обмена |
| `ОбменДаннымиПереопределяемый` | Регистрация планов обмена, правил выгрузки/конвертации и ограничений миграции данных |
| `ОбменДаннымиXDTOСервер` | Универсальный формат обмена `EnterpriseData` (КД 3) |

- Не удаляй регистрацию изменений через прямое очищение таблицы регистрации без учёта `НомерОтправленного` / `НомерПринятого` сообщения обмена: сделай это только штатными методами `ОбменДаннымиСервер`, иначе нарушишь квитирование узлов.
- При программной записи объектов в миграциях и обработчиках обновления учитывай флаг `ОбменДанными.Загрузка = Истина`: он подавляет бизнес-проверки подписок и авторегистрацию к обратной отправке, поэтому в обычном прикладном коде включать его для обхода проверок запрещено.

## 4. Префиксы нумерации и разделение данных (`ОбластиДанных` / `1С:Фреш`)

- **Префиксация объектов (`ПрефиксацияОбъектовКлиентСервер`, `ПрефиксацияОбъектовСобытия`)**: итоговый номер документа или код справочника формируется из префикса информационной базы (узла РИБ) и префикса организации. Не склеивай и не отрезай первые символы `Номер` вручную через `Лев()`/`Прав()` — используй публичные функции выделения префикса и номера на печать.
- **Разделение данных (мультитенантность / `ОбщегоНазначенияПовтИсп.РазделениеВключено()`)**:
  - В разделённой базе общие справочники и регистры разделены общим реквизитом области данных (`ОбластьДанныхОсновныеДанные`), а неразделённые объекты доступны только привилегированному или административному контексту.
  - Регламентные задания в модели сервиса должны запускаться в контексте конкретной области данных (или обходить активные области через API подсистемы разделения), иначе запрос к разделённым таблицам без установленного разделителя упадёт по ошибке использования разделителей.

## 5. Многоязычность и локализация (`НСтр`, `СтроковыеФункцииКлиентСервер`)

- Все пользовательские сообщения, заголовки колонок, тексты ошибок и шаблоны формируй через `НСтр("ru = '...'")` с подстановкой параметров через `СтрШаблон(НСтр(...), Параметр1, Параметр2)`, а не конкатенацией кусков фраз через `+` (порядок слов в языках локализации отличается).
- В модулях с поддержкой нескольких языков интерфейса не кэшируй результат `НСтр(...)` в глобальных/повторно используемых структурах без учёта `КодЯзыка` текущего пользователя сеанса.
