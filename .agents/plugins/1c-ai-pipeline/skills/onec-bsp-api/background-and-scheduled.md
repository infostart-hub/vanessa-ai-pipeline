# Фоновые операции и регламентные задания

Карта для ДлительныеОперации (фоновая работа, запущенная из формы) и подсистемы РегламентныеЗадания (управление заданиями из кода). Имена и регионы подтверждены для БСП 3.1.11. Для целевого проекта сверяй модуль, сигнатуру и регион по модели EDT.

## Модули

| Модуль | Роль |
|---|---|
| ДлительныеОперации | Стабильный серверный API запуска, прогресса, отмены и состояния |
| ДлительныеОперацииКлиент | Ожидание завершения и параметры формы ожидания |
| ДлительныеОперацииВызовСервера | Только служебный ФоновоеЗаданиеЗавершено; не вызывай |
| РегламентныеЗаданияСервер | Стабильный серверный API: найти, добавить, изменить, удалить задание, расписание и использование |
| РегламентныеЗаданияКлиент, РегламентныеЗаданияСлужебный | Служебные |
| РегламентныеЗаданияПереопределяемый | Хук ПриОпределенииНастроекРегламентныхЗаданий |

Не существуют: общий модуль РегламентныеЗадания без суффикса, ДлительныеОперацииСлужебный (служебные методы лежат в самом ДлительныеОперации), РегламентныеЗаданияСервер.ПараметрыДобавленияЗадания. Расписание в структуру и обратно переводят ОбщегоНазначенияКлиентСервер.РасписаниеВСтруктуру / СтруктураВРасписание.

## Фоновая операция из формы

- Длительный серверный вызов из формы: ДлительныеОперации.ВыполнитьФункцию(ПараметрыВыполнения, ИмяФункции, Параметр1…7) или ВыполнитьПроцедуру, затем ДлительныеОперацииКлиент.ОжидатьЗавершение с ОписаниеОповещения. Имя функции или процедуры — второй параметр, не последний.
- Параметры: ПараметрыВыполненияФункции(ИдентификаторФормы) и ПараметрыВыполненияПроцедуры(). Значения параметров и результата сериализуемые; результат приходит через АдресРезультата временного хранилища.
- Прямой ФоновыеЗадания.Выполнить обходит обработку ошибок и журналирование БСП. ВыполнитьВФоне не рекомендован для нового кода, ЗапуститьВыполнениеВФоне устарел.
- Фоновое задание выполняется вне транзакции формы. Сообщения из него забирает СообщенияПользователю; прогресс — СообщитьПрогресс в теле задания и ВыводитьПрогрессВыполнения в параметрах ожидания. Прогресс не канал для частей результата.
- ЗаданиеВыполнено вызывает исключение при аварийном завершении, если не запрошен расширенный результат. ОтменитьВыполнениеЗадания только инициирует отмену.
- Многопоточные ВыполнитьФункциюВНесколькоПотоков / ВыполнитьПроцедуруВНесколькоПотоков: тип набора параметров и ограничение числа потоков сверяй по сигнатуре версии проекта; каждая порция обрабатывает свои ошибки сама.

## Регламентное задание

- Метаданные регламентного задания, его метод и расписание по умолчанию находятся в конфигурации; в EDT проверь объект РегламентноеЗадание, его имя метода и общий модуль обработчика.
- Найди в исходниках БСП проекта, как типовые обработчики регламентных заданий начинают работу, и повтори этот вызов в новом обработчике. Без него задание обходит проверки БСП для регламентной работы. Не придумывай имя вызова; сверь его по типовому обработчику той же конфигурации.
- Управление из кода: РегламентныеЗаданияСервер.НайтиЗадания(Отбор) всегда с отбором; ДобавитьЗадание(Параметры) со структурой и обязательным полем Метаданные; ИзменитьЗадание, УдалитьЗадание, УстановитьРасписаниеРегламентногоЗадания, УстановитьИспользованиеРегламентногоЗадания. Модуль серверный; с клиента — только через серверный вызов.
- В модели сервиса ДобавитьЗадание создаёт запись очереди заданий, а не платформенное регламентное задание.
- Одно задание с итерацией внутри обработчика лучше набора заданий с одними метаданными и разными ключами.
- Обработчик, который записывает учётные данные за прошедший период, обязан учитывать даты запрета изменения: явная проверка ДатыЗапретаИзменения.ИзменениеЗапрещено или поведение подписок, подтверждённое для этих объектов (см. data-protection.md). Повторный запуск за тот же период не должен создавать повторных изменений.
- Решение о выключении задания при ошибке — продуктовое; по умолчанию ошибку записывают в журнал регистрации и передают дальше.
