# LLMINSTALL — Протокол для ИИ-агента по установке и настройке `1c-ai-pipeline`

Эта инструкция предназначена для автономного выполнения ИИ-агентом (**OpenAI Codex**, **Claude Code**, **Cursor** и др. совместимыми клиентами **Agent Plugins 1.0**), когда пользователь просит установить и настроить плагин `1c-ai-pipeline`.

## Жёсткие правила выполнения для агента (прочитай перед первой командой)

1. **Один непрерывный проход до конца — без промежуточных отчётов**:
   - **ЗАПРЕЩЕНО** останавливаться на полпути и писать «плагин установлен, но ещё не настроен / `--check` ещё не выполнен».
   - Выполни последовательно **все шаги с 1 по 5** в рамках одного поручения и выдай пользователю **один готовый итоговый отчёт** только после финального запуска `pipeline-deploy.cjs doctor`.
2. **Пользователь — аналитик или разработчик 1С, он НЕ обязан знать Git и командную строку**:
   - **ЗАПРЕЩЕНО** просить пользователя вручную вводить в терминале `git config`, `git clone`, `ssh-keygen` или любые консольные команды.
   - Всё техническое (установку `Git`, `mise`, `Node.js`, настройку `user.name` / `user.email`, клонирование репозиториев, открытие страницы скачивания `1С:EDT` в браузере) делай **сам**, а у человека спрашивай в чате только простые человеческие данные: его **Имя, Фамилию, корпоративный e-mail**, **ссылку от релиз-инженера** и **путь к тестовой копии базы 1С**.
3. **Не пугай пользователя внутренним мусором `PATH` на корпоративных ПК**:
   - На Windows в `PATH` часто встречаются сломанные сторонние обёртки `node.cmd` или нерабочие ссылки `WinGet\Links\codex.exe`. Не пиши пользователю пугающих фраз вроде *«обнаружены неработающие Node.js и Codex»* — спокойно используй `mise exec -- node` и штатный бинарник клиента ИИ из вывода `pipeline-deploy.cjs doctor --json`.
4. **Не трогай запущенные процессы 1С и рабочие базы**:
   - Не останавливай процессы `1cv8`, `1cv8c`, `1cedt`, `rphost`, `rmngr`, `ragent` и не затирай существующие пользовательские конфиги (аккуратно дополняй JSON/TOML).
5. **На Windows выполняй сетевые, установочные и Java-команды ВНЕ песочницы (outside sandbox / escalated)**:
   - В десктопных клиентах ИИ на Windows (Codex Desktop, Cursor и др.) стандартная песочница AppContainer блокирует локальные TCP loopback-сокеты Java NIO (`java.io.IOException: Unable to establish loopback connection`), а также системные установщики `winget`, `git` и `p2.director` при сборке Maven/Tycho и установке плагина в 1С:EDT.
   - Поэтому на Windows **сразу запрашивай запуск вне песочницы (с повышенными разрешениями в клиенте ИИ)** для вызовов `winget`, `git clone`, `mise` и `pipeline-deploy.cjs deploy` / `deploy-edt`. Если команда вернула `sandbox_loopback_blocked` или `Unable to establish loopback connection` — немедленно перезапусти её вне песочницы, не заставляя пользователя разбираться с Java.
6. **Не создавай лишних файлов-отчётов на диске пользователя**:
   - **ЗАПРЕЩЕНО** записывать в рабочую папку пользователя отчётные файлы `.md` / `.txt` об итогах установки. Итоговый ответ пиши только в чат лаконично (12–20 строк по делу).

## Шаг 1. Проверка `Git` и клонирование головного репозитория плагина

1. Проверь наличие `git` (`git --version`). Если на Windows `git` ещё не установлен — установи его сам без вопросов пользователю:
   ```powershell
   winget install Git.Git --accept-source-agreements --accept-package-agreements
   ```
   *(Если в текущей сессии `PATH` ещё не обновился, вызывай `"C:\Program Files\Git\cmd\git.exe"` напрямую.)*
2. Если ты ещё не находишься внутри локального клона `vanessa-ai-pipeline`, склонируй его в постоянный каталог инструментов пользователя (`~/tools/vanessa-ai-pipeline` на macOS/Linux или `%USERPROFILE%\tools\vanessa-ai-pipeline` на Windows):
   ```sh
   git clone https://github.com/infostart-hub/vanessa-ai-pipeline.git
   ```
3. Перейди в корень клона `vanessa-ai-pipeline`. Пакет плагина расположен внутри по пути `.agents/plugins/1c-ai-pipeline`.

---

## Шаг 2. Подготовка `mise` и `Node.js 24.18.1`

Для работы защитных хуков (`hooks/*.cjs`), запускателя `bin/vanessa-runner-mcp.cjs` и оркестратора развёртывания `bin/pipeline-deploy.cjs` нужен **Node.js >= 18** (в `mise.toml` закреплена LTS-версия **`24.18.1`**).

1. Проверь наличие `mise`. Если `mise` ещё не установлен — установи его под текущую ОС:
   - **Windows**: `winget install jdx.mise --accept-source-agreements --accept-package-agreements` *(либо в PowerShell: `irm https://mise.run/powershell | iex`)*
   - **macOS**: `brew install mise` *(или `curl -fsSL https://mise.run | sh`)*
   - **Linux**: `curl -fsSL https://mise.run | sh`
2. В корне клона `vanessa-ai-pipeline` выполни:
   ```sh
   mise trust
   mise install
   ```
3. Если в неинтерактивной оболочке обычный вызов `node --version` отсутствует или падает на стороннем битом скрипте в `PATH`, запускай все дальнейшие команды Node через `mise exec -- node ...`.

## Шаг 3. Автоматическое развёртывание окружения 1С и открытие загрузки 1С:EDT (`pipeline-deploy.cjs deploy`)

**До** регистрации плагина в клиенте запусти штатный оркестратор развёртывания из корня клона `vanessa-ai-pipeline` **с флагом `--open-edt-download`**:

- **На Windows**:
  ```powershell
  mise exec -- node .agents/plugins/1c-ai-pipeline/bin/pipeline-deploy.cjs deploy --fix-user-path --open-edt-download --json
  ```
- **На macOS / Linux**:
  ```sh
  mise exec -- node .agents/plugins/1c-ai-pipeline/bin/pipeline-deploy.cjs deploy --open-edt-download --json
  ```

Что эта команда делает автоматически и идемпотентно:
1. На Windows (при флаге `--fix-user-path`, если глобальный `node` в `PATH` отсутствует или сломан) безопасно поднимает `%LOCALAPPDATA%\mise\shims` в начало пользовательского `Path` без повреждения системных переменных `REG_EXPAND_SZ`.
2. Клонирует в соседние gitignored-каталоги три адаптированных репозитория из `infostart-hub`:

   | Каталог (в `.gitignore`) | Публичный форк (`origin`) | Базовый апстрим (`upstream`) |
   |---|---|---|
   | `./edt-mcp` | `https://github.com/infostart-hub/edt-mcp-aiadopted.git` | `https://github.com/DitriXNew/EDT-MCP.git` |
   | `./vanessa-runner` | `https://github.com/infostart-hub/vanessa-runner-aiadopted.git` | `https://github.com/vanessa-opensource/vanessa-runner.git` |
   | `./vanessa-automation` | `https://github.com/infostart-hub/vanessa-automation-aiadopted.git` | `https://github.com/Pr-Mex/vanessa-automation.git` |
3. Устанавливает OneScript `2.2.1` (через `ovm` в `vanessa-runner` на Windows или нативный OneScript на macOS/Linux), ставит пакеты `opm` и применяет патч `patches/autumn-mcp-discovery.patch`.
4. Проверяет платформу **1С:Предприятие 8** (`1cv8`), **OneScript**, **1С:EDT** и настройку автора в **Git** (`doctor.gitIdentity`: `user.name` и `user.email`).
5. Обрабатывает **1С:EDT**:
   - если на компьютере ещё не был установлен `Git`, на Windows автоматически доустанавливает `Git.Git` через `winget` перед клонированием форков (`./edt-mcp`, `./vanessa-runner`, `./vanessa-automation`);
   - если **1С:EDT уже установлена** (поддерживаются линейки **`2025.2`, `2026.1` и `2026.2`** — при наличии нескольких версий на диске плагин автоматически ставится **во все закрытые поддерживаемые установки 1С:EDT** за один проход) — **собирает локальный клон `./edt-mcp` из исходников через `mise` (`mise install` + `mise run build`)**, ставит плагин `com.ditrix.edt.mcp.server` через штатный `p2.director`, обходит занятый порт `8765` (переключая на свободный `8766`) и сохраняет все пути в `settings.json`;
     *(Всегда собирай `EDT MCP` именно из локального клона `./edt-mcp`, чтобы ты и пользователь могли в любой момент доработать и пересобрать форк под свои задачи. На Windows обязательно выполняй этот шаг вне песочницы клиента ИИ, чтобы не блокировались локальные сокеты Java. Крайний резервный флаг `--from-release` допустим только если корпоративная сеть на ПК полностью блокирует Maven.)*
   - если на компьютере обнаружена только устаревшая версия 1С:EDT младше `2025.2` (`edt.status == "edt_version_unsupported"`) — вежливо сообщи пользователю поставить актуальную **1С:EDT `2026.1` или `2026.2`** через уже установленный у него **1C:EDT Start**;
   - если **1С:EDT на компьютере НЕ установлена** — благодаря флагу `--open-edt-download` **автоматически открывает официальную страницу скачивания `https://edt.1c.ru/` прямо в браузере пользователя** (`step: "open_edt_download_browser"`).

> **Если порт `8765` занят посторонним процессом** (`doctor.edt.status == "port_conflict"` или `port8765Conflict == true`, например другой локальный процесс отвечает `HTTP 404`): запомни свободный порт `doctor.edt.suggestedPort` (обычно `8766`) — после установки в клиенте синхронизируй URL `edt-mcp` на `http://127.0.0.1:<suggestedPort>/mcp`.

## Шаг 4. Подключение плагина `1c-ai-pipeline` в клиенте ИИ

Возьми путь к рабочему исполняемому файлу клиента из поля `doctor.aiClients` отчёта Шага 3 (на Windows для десктопного Codex используй найденный `%LOCALAPPDATA%\OpenAI\Codex\bin\*\codex.exe`, не вызывай битую ссылку `WinGet\Links\codex.exe`):

- **OpenAI Codex** (CLI или Codex Desktop):
  ```sh
  "<CODEX_EXECUTABLE>" plugin marketplace add "<АБСОЛЮТНЫЙ_ПУТЬ_К_КЛОНУ>" --json
  "<CODEX_EXECUTABLE>" plugin add 1c-ai-pipeline@1c-ai-pipeline --json
  ```

  ```text

  ```
  *(либо через CLI `claude` / флаг `--plugin-dir <АБСОЛЮТНЫЙ_ПУТЬ_К_КЛОНУ>/.agents/plugins/1c-ai-pipeline`)*
- **Cursor**:
  Подключи пакет через совместимый манифест `<АБСОЛЮТНЫЙ_ПУТЬ_К_КЛОНУ>/.cursor-plugin/marketplace.json` (`.agents/plugins/1c-ai-pipeline`).

## Шаг 5. Финальная верификация (`mise run check` и `doctor`) и человеческий диалог с пользователем

В корне `vanessa-ai-pipeline` выполни обе финальные проверки:

```sh
mise run check
mise exec -- node .agents/plugins/1c-ai-pipeline/bin/pipeline-deploy.cjs doctor
```

Убедись, что:
- все 3 защитных хука (`SessionStart`, `PreToolUse`, `PostToolUse`) вернули код `0`;
- если на компьютере есть платформа 1С / OneScript — `vanessa-runner-mcp.cjs --check` вернул `"ready": true` (код `0`), а `doctor` подтвердил ответ MCP-сервера `Vanessa Runner` (71 инструмент) и проверил наличие автономного сервера `ibsrv` / `ibcmd` и список баз в `ibases.v8i`;
- если окно `1С:EDT` открыто (`doctor.edt.status == "ready"`), **обязательно проверь статус `1С:Напарник` (`doctor.edt.workmate`) и живую связку `EDT-MCP ↔ 1С:Напарник`**:
  - если `workmate.status == "ready"` — при необходимости раскрой группу `enable_toolset(["workmate"])` и выполни контрольную проверку моста (`ask_workmate` с `workmateTool="JShellSession"`, `workmateArgs="{}"`, `waitSeconds=15` → `get_job_status`);
  - если `workmate.status` равен `"no_client_token"`, `"disabled"`, `"not_installed"` или `"needs_activation_and_live_check"` — сам открой пользователю в браузере страницу получения ключа командой `mise exec -- node .agents/plugins/1c-ai-pipeline/bin/pipeline-deploy.cjs open-edt-download --workmate` (`https://code.1c.ai/`) и попроси активировать ключ в Пункте Г ниже.

### Что обязательно написать и спросить у пользователя в итоговом ответе (простым языком, без команд терминала!)

1. **Короткая сводка того, что ты уже установил и проверил**:
   - Плагин `1c-ai-pipeline` (45 навыков + 3 защитных хука): установлен и включён.
   - Платформа 1С (включая наличие Автономного сервера `ibsrv` / `ibcmd`), список баз из `ibases.v8i` и готовность `Vanessa Runner MCP` (`ready: true`).
   - Статус `1С:EDT`, `EDT MCP` и **`1С:Напарник` (`Workmate ↔ EDT MCP`)**.
   - Если на Шаге 3 менялся пользовательский `Path` Windows (`windows_user_path.changed == true`), предупреди: **перед рабочей задачей один раз полностью закройте и заново откройте приложение Codex / Cursor** (чтобы оно подхватило новый `Path`).

2. **Пять простых пунктов для пользователя (НЕ пиши команды `git config` / `git clone` — делай их сам после ответа пользователя!)**:

   - **Пункт А. Имя и корпоративная почта (если `doctor.gitIdentity.configured == false`)**:
     Прямо спроси у пользователя в чате:
     > **1. Как вас зовут (Имя и Фамилия) и какой у вас корпоративный e-mail?**
     > Напишите их прямо сюда в ответ — я сам настрою автора изменений на вашем компьютере (никаких команд вводить не нужно).
     *(Когда пользователь пришлёт имя и почту — сам выполни `node "<ПУТЬ_К_КЛОНУ>/.agents/plugins/1c-ai-pipeline/bin/pipeline-deploy.cjs" setup-git --name "<ФИО>" --email "<EMAIL>"`.)*
     Если `doctor.gitIdentity.configured == true` — просто подтверди, какие имя и e-mail уже настроены (`userName <userEmail>`), и спроси, верны ли они.

   - **Пункт Б. Доступ к конфигурации 1С у релиз-инженера**:
     Объясни без слова «клонировать»:
     > **2. Доступ к проекту конфигурации 1С (КА / ЗУП / вашей базе):**
     > Напишите вашему **релиз-инженеру**: *«Выдай мне, пожалуйста, доступ к репозиторию нашей конфигурации 1С на мою корпоративную почту и пришли ссылку»*. Когда он пришлёт ссылку — просто вставьте её сюда в чат, я сам скачаю проект на ваш компьютер (а если релиз-инженер попросит SSH-ключ — скажите мне, я сам создам его и дам готовую строку для отправки).

   - **Пункт В. Установка 1С:EDT (если `edt.status == "edt_not_installed"`)**:
     Скажи пользователю:
     > **3. Установка 1С:EDT (я уже открыл страницу скачивания в вашем браузере):**

Скачайте установщик **1C:EDT Start**, поставьте **1С:EDT версии 2025.2, 2026.1 или 2026.2**, один раз откройте и закройте её и напишите мне *«EDT поставил»* — я сам соберу и подключу к ней плагин. *(При этом работать напрямую с тестовой копией базы через Платформу 1С можно уже сейчас, не дожидаясь EDT.)*

   - **Пункт Г. Активация `1С:Напарник` и проверка связи с `EDT MCP` (если `edt.workmate.status != "ready"`)**:
     Скажи пользователю точно так же просто, как про лицензию:
     > **4. Активация 1С:Напарник в 1С:EDT:**

В окне **1С:EDT** откройте **Окно → Параметры → 1С:Напарник** (либо боковую панель «1С:Напарник»), включите его и вставьте ключ (сам ключ в чат присылать не нужно!). Подтвердите в чате, какую из найденных тестовых баз используем (или пришлите путь к папке / адрес Автономного сервера `http://localhost:...`, пароль в чат не пишите).
